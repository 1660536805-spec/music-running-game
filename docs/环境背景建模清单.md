## 0. 前提约束（所有补充工作必须遵守）

| 约束 | 说明 | 对"补建模"的影响 |
|---|---|---|
| **单文件** | 全部代码在 `声浪星球.html`，无外部模块 | 新增元素只能是内联 helper 或就地内联几何 |
| **程序化低多边形** | 只用 `Icosahedron / Cylinder / Plane / Lathe / Torus / Ring / Box / Octahedron / Cone` 等基础几何 | 不能引入模型文件、不能做雕刻级细节 |
| **贴图仅限程序化 canvas** | 只有 `ptex()`（渐变/条带/噪点）与 `glowTex()`（径向辉光），禁用照片纹理、法线贴图 | 所有"材质感"靠顶点色 + emissive + 低面数造型 |
| **`rnd()` 是纯随机流** | `rr(a,b)` 只改区间不影响后续；但**任何改变调用次数**（`ri()` 返回值、循环次数）都会打乱整场景布局 | 新元素必须**零 rnd 消耗**（用确定性写法），否则只在场景末尾追加 |
| **每场景独立种子** | `srand()` 分场景固定，保证构图可复现 | 四场景互不干扰，可单独改 |
| **无后处理** | 无 Bloom/SSAO/FXAA 模块 | 所有"发光"靠自发光材质 + 加法混合 + Sprite 伪造 |

## 4. 补齐工作方案（具体做什么 · 怎么做 · 输出什么）

**通用原则**：
- 新增**确定性**元素（零 `rnd()`）：可在任意位置插入，零漂移 —— 见 `gemCluster/rockArch/ringMonument` 的既有范式。
- 新增**随机**元素：只在对应 `buildXxx()` 函数**末尾**追加，或采用"burn 补偿"对齐随机序列。
- 改现有元素：只动参数区间 / 颜色 / 几何参数，**绝不动调用次数**。
- CAVE 新增需注意 calls 已达 1683，优先用"单几何多顶点色"或合并 group。

### ☁️ 天空占比校正 + DESERT 中景重配（本轮 · 用户指定「先做天空」）

**问题量化**：用「**逐行天空占比剖面**」测出 TER 天际线 —— 参考 **61.9%** vs 渲染 **46.4%**（差 **−15.5pt**，即我们少了约 15% 画面高度的天空）。

**关键认识：天际线位置只由相机 `pitch` 决定**（地面延伸足够远时），与相机高度、地形尺寸无关：
`y_horizon = 0.5 + pitch / vFOV`
- 原 desert `pitch −3°, fov 60` → `0.5 − 0.05 = 45%`（与实测 46.4% 吻合）
- 目标 61.9% → **`pitch = +7.14°`**

| 岩丘 / 台地 | 岩丘 y 拉伸 `0.6–1.0→1.7–2.8`；台地高 `3–10→7–14`、半径 `2.2–5.0→4.0–8.5` | 把中景两侧"填实"，避免天空修好后画面反而变空（**只改 `rr` 区间，不改调用次数 → 零漂移**） |

**方法论教训（重要，已固化）**
- **5×5 网格色差会把"地平线整体错位"这类系统性偏差糊掉**——必须用「逐行天空占比剖面」才能测出天际线。
- **宫格缩略图的长宽比会骗人**：参考图在小尺度下"看起来"地面更高；逐像素采样（`y=55%` 仍 4/4 为蓝）才确认天际线确实在 **62%**。→ 判读构图务必回到 1:1 原尺度 + 数值采样，别靠缩略图目测。

**本轮校验**：`desert` 天际线 **61.3% vs 参考 61.9%**（差 0.6pt）；网格色差 `y2x2 0.37→0.06` · `y1x3 0.36→0.06` · `y1x1 0.35→0.15`；`home/cave/base` 的 `heroC` **逐位不变**（改动完全隔离在 desert）；budget `desert 677/30.5k`（<700 红线内）；playtest 跳跃 `lifted=true`、**零控制台报错**。

### ⏳ 剩余项（下一轮可选，风险偏高）

- **`debrisChunk` 碎裂边缘 / 悬空碎块**：需改共享的 `floatingIsland()`（影响 HOME/DESERT/BASE 三处岛体），风险高，需独立一轮
- **HOME 右下角近景**：参考是**亮粉水晶簇**、我们是大片绿草坡（`y4x4 d0.40`）；可用 `dseq()` 补一簇近景水晶
- **HOME / CAVE 天空占比**：同理用逐行剖面测出（HOME 参考 79.6% vs 渲染 87.4%，我们多了些天空），需各自调相机 pitch —— 与 DESERT 同法，但会改动该场景取景，建议逐场景单独一轮
- **画面底行前景与岛体布局的进一步对齐**：需移动主岛 / 前景地形大件

## 7. 一句话结论

> **四个场景的"主干环境"（地形/天空/光照/建筑/植被/岩石晶体/天体/粒子）均已建模且在案**；
> 缺的是**近景与交界的细节层**（瀑布落水、地被、建筑门窗、云影、沙纹）与**生命感层**（风摆、花瓣、飞鸟）。
> 两者均已用**零 `rnd` 消耗的确定性 helper（`dseq()` 家族）** 补齐——**S1 / S2 / S3 全部落地，四场景 `heroC` 全程零漂移**。
> 剩余项（碎裂边缘、DESERT 天空占比、HOME 近景水晶）**均需移动大件或改共享几何**，风险偏高，留待后续独立轮次。
