### 0.3 设计红线（不可越界）

1. **单文件 + 纯程序化 + 无后处理**：不引入任何外部依赖、不新增 `.glb`、不使用 `EffectComposer`。
2. **视觉复刻不被玩法破坏**：每场景的构图/机位/调色板对应参考图定帧。**玩法对象只能"叠加"，不得移动既有地物、不得改动定帧机位的基准值**。
3. **相机策略受限**：由于定帧是核心验收标准，**禁止做传统"后上方跟随"第三人称相机**。玩法相机必须满足：任一时刻的构图仍落在参考图容差内（见 §3.1 方案 B）。
4. **`rnd()` 纯随机流神圣不可侵犯**：新增随机外观元素一律走 `dseq(新种子)`；若必须动 `rnd()` 调用次数，需成对 burn 补偿，并跑 `__info()` 逐位校验四场景 `heroC` 零漂移。
5. **性能红线**：cave 已 1725 draw calls（最高），新增玩法对象须**共享 geometry / 合并 / 实例化**，四场景 calls 分别不得超过 700(home/desert) / 1900(cave) / 1000(base)。

## §1 设计框架与目标（一页纸）

### 1.1 一句话核心体验

> 你带着一台播放器降落在一颗灰暗的星球上；随着歌响起，地貌苏醒、晶体亮起、传送门运转——你**跟着歌的节拍跑跳、收集音乐能量**，把整颗星球重新点亮，然后带着点亮它的那首歌继续远航。

### 1.2 三条设计支柱

| 支柱 | 含义 | 对玩法的约束 |
|---|---|---|
| **P1 · 音乐即世界** | 节拍、曲风、段落直接驱动机关与动态 | 所有节奏型玩法必须挂到 `BeatClock`，不得自造计时器 |
| **P2 · 跑跳即演奏** | 移动动作踩在拍点上获得增益，把跑酷缝进音游 | 跳跃/冲刺/收集都需读 beat 窗口 |
| **P3 · 一图一定帧** | 四场景构图锁死为参考图定帧 | 玩法层"只叠加不动既有"，相机策略受限（红线 3） |

### 1.3 设计目标

| 维度 | 目标 | 验收 |
|---|---|---|
| **体验** | 3 秒看懂"歌变星球"，30 秒上手（跑/跳/收三个动作），3 分钟完成一首歌的关卡 | 首次进入无需教程即可完成 desert 收集 3 晶体 |
| **内容** | 1 枢纽 + 3 曲境星球；每星球 1 首歌 / 1 组目标 / 1 道传送门 | 四场景全部可玩通 |
| **技术** | 在现有单文件架构上最小侵入叠加；零外部依赖；`heroC` 零漂移；零控制台报错 | `playtest` 四场景通过 + `__info()` 逐位一致 |

## §2 核心玩法（Core Loop）

### 2.1 三级循环

| 层级 | 时长 | 循环内容 | 反馈强度 |
|---|---|---|---|
| **微循环** | ~30 秒 | 跑 → 踩点跳 → 吸附收集晶体 → 计数 +1 | 每次收集：吸入动画 + 音效 + 计数弹跳 |
| **中循环** | ~3 分钟（一首歌） | 进入星球 → 沿路径收集 N 个晶体 → 集齐后传送门亮起 → 激活传送 | 集齐瞬间：全场景脉冲 + 门体加速旋转 + 和弦 |
| **宏循环** | ~10 分钟（一轮） | 枢纽选曲 → 通关三星球 → 解锁图鉴条目 & 新曲 → 返回枢纽 | 通关：结算卡 + 图鉴点亮动画 |

### 2.2 "歌曲 = 星球 = 关卡"的世界观映射

现有 HUD 已埋好这个映射（`musicCard` 文案），本方案把它升格为世界观主线：

| 场景 | 星球 | 曲目（现有文案） | 关卡定位 | 机制侧重 |
|---|---|---|---|---|
| **HOME** | 星港枢纽 | —（`选择歌曲`） | 枢纽/菜单 | 无跑动，纯 UI 交互 |
| **DESERT** | 晴天星 | 《晴天》 | **跑酷关** | 节拍跳跃 + 长距离冲刺 |
| **CAVE** | 夜曲星 | 《夜曲》 | **探索关** | 昏暗寻路 + 晶体采集 |
| **BASE** | 稻香星 | 《稻香》 | **结算/经营关** | 资源结算 + 图鉴展示 |

> 叙事：HOME 是母港，DESERT/CAVE/BASE 是三颗待点亮的曲境星球。玩家在母港选歌，降落到对应星球，用节拍能量唤醒它。

## §3 主要机制（逐条细化：现状 → 设计 → 关联 → 优先级）

### 3.1 移动机制 ★ P0

**现状**：hero 固定于 `baseY`，仅 `jump.y` 垂直位移；姿态由 `poseHero` 的 `run/idle` 驱动。

**设计**：
- **前进轴**：角色沿场景主轴（z 轴负方向 = "远方"）移动，用 `speed`（默认 4.5 u/s）前进；左右用横移微调（±1.6 u/s）。
- **贴地**：每帧用场景高度函数求 `ground(x,z)`，令 `hero.y = ground + jump.y`。desert 用 `dh()`、cave 用洞内高度、base 用 `fh()`、home 用 `gh()`——**函数已存在，直接复用**。
- **跳跃**：沿用现有 `jump`（`v0=6, g=18`，滞空 ≈0.67s）。踩点起跳（beat 窗口内）→ `v0=7.2`（跳更高更远）。
- **姿态扩展**：`poseHero` 增加 `'jump'`（腾空：手臂上举、腿收）与 `'land'`（落地缓冲 0.15s）。

**相机方案（红线 3 的解法）**：
- 方案 A（**推荐**）——**舞台式固定机位**：相机完全不跟随，角色在"舞台"内移动。与视觉复刻天然兼容，且类似《纪念碑谷》的固定构图美学。代价：纵深有限，关卡更像"横向卷轴 + 纵深带"。
- 方案 B——**限定微跟随**：相机基准值 = `CAM[k]` 定帧值，允许围绕基准做 **≤3% 视口** 的平移/俯仰补偿，跟随系数 `k=0.8` 指数平滑。需在关卡入口/出口校验构图仍在参考图容差内。
- 决定：**M1 先用方案 A 落地闭环，M2 再评估是否升级方案 B**。

**关联**：依赖 `Input`(#1)；被 `Collectible`/`CameraRig` 依赖。
**优先级**：P0，M1 核心。

---

### 3.2 音乐节拍机制（BeatClock）★ P0

**现状**：`scheduleAudio()` 用 `nextBeat < actx.currentTime + 0.18` 循环排 `kick/hat`，`beatCount` 自增，但**不对玩法层暴露**。

**设计**：
- 把节拍排程升级为**事件总线**：`BeatClock.onBeat(fn)`，每次 kick 触发时广播 `{t, index, isStrong(kick=强拍/hat=弱拍)}`。
- **拍点窗口**：`|now - beatTime| <= 0.09s` 判定为"踩点"。动作（跳/收集/冲刺）在窗口内 → `perfect`，否则 `good`。
- **视觉节拍化（可选增强）**：现有 `_sway`/`_petals`/`_flocks` 的相位可叠加一个随 `beat pulse` 的脉冲项（幅度 ≤ 3%，不影响构图）。**新增对象走 dseq，零漂移**。
- **旋律层**（P1）：为每星球叠一条 2~4 音的动机（复用 `AudioContext` 振荡器），让它"真的像一首歌"。

**关联**：`PlayerController` 读窗口判踩点；`Collectible` 按节拍生成；`VFX` 按节拍脉冲。
**优先级**：P0（基础 beat 事件）/ P1（旋律层）。

---

### 3.3 收集机制（音乐晶体）★ P0

**现状**：`userData.crystals` 仅存在于 cave，只做 `scale` 呼吸；desert 有 `gemCluster` 但非可采对象。

**设计**：
- **可采对象**：给晶体簇打标记 `userData.collectible = true`、`userData.ctype = 'shard'`。
- **吸附采集**：角色进入 `R=2.5` 内自动吸附（0.25s 缓动飞向角色）→ 播 `collect` 音效 → `GameState.collected++` → HUD 计数 +1 → 粒子爆。
- **生成策略**：desert 需**新增** 3 个可采晶体（沿路径分布），**走 `dseq(0xC011)` → 不消耗 `rnd()` → 零漂移**；cave 复用现有 `caveCrystals`。
- **变体**：`shard`（青/普通）、`note`（金/稀有，+2 分）、`core`（紫/任务必需）。

**关联**：依赖 `PlayerController`；驱动 `TaskSystem`、`VFX`、`HUD`。
**优先级**：P0，M1 核心。

---

### 3.4 传送装置机制（Portal）★ P1

**现状**：`ringGate()`（分段石环 + 青蓝内环）+ `beam`（能量柱，仅缩放呼吸），无判定。

**设计**：
- 每颗可玩星球有 **1 道传送门** = `ringGate` + `beam`。
- **状态机**：`dormant`（暗、慢转）→ `charged`（集齐晶体后：beam 亮度拉满、环加速自转、脉冲音）→ `activated`（角色进入判定圈 → 场景切换 + 白闪过渡）。
- 把 `beam` 缩放呼吸频率与 `BeatClock` 绑定（带电后频率 ×1.5）。

**关联**：依赖 `TaskSystem`（集齐才亮）、`GameState`（激活即切场景）。
**优先级**：P1（没有它，中循环无法收束）。

---

### 3.5 任务与进度机制（TaskSystem）★ P0

**现状**：`taskCard()` 硬编码三项字符串。

**设计**：
- 三项任务**数据化**：`LevelDef.tasks = [{id:'shards', need:3, label:'收集 3 个音乐晶体'}, {id:'portal', need:1, ...}, {id:'summit', need:1, ...}]`。
- `TaskSystem.progress(id, n)` → HUD 重渲染该行（勾选/数值）。
- **各场景任务差异**：
  - DESERT：`shards 3/3` + `summit 1/1`（到达远处山顶）+ `portal`（顶部传送）
  - CAVE：`shards 3/3` + `portal 1/1`
  - BASE：无任务（结算面板）
- 三项既是**关卡目标**，也是**通关判定**。

**关联**：被 `Portal`/`HUD`/`GameState` 依赖。
**优先级**：P0，M1 就需跑通 `shards` 一项。

---

### 3.6 歌曲系统（SongDB）★ P1

**现状**：`musicCard(name, artist, cur, total, seed)` 是纯静态渲染。

**设计**：
- `SongDef = { id, name, artist, planet, scene, bpm, duration, palette, difficulty, unlock }`。
- `musicCard` 改为从 `SongDB.cur` 渲染；歌名/时长直接来自数据。
- **切歌影响**：`bpm`（→ 节拍器速度）、`palette`（→ HUD 强调色，**不改场景本体色，守住视觉复刻**）、`difficulty`（→ 机关密度）、通关条件。
- 现有三首（晴天/夜曲/稻香）即为初始曲库。

**关联**：`HUD` 渲染；`BeatClock` 读 bpm；`Codex` 读解锁状态。
**优先级**：P1。

---

### 3.7 图鉴系统（Codex）★ P1

**现状**：`星球图鉴` 按钮存在但 `data-go="home"`，无实际页面。

**设计**：
- 覆盖层页面（复用 HUD 玻璃卡风格），两栏：**星球图鉴**（四格，未解锁为剪影）+ **歌曲收藏**（已通关歌曲卡片 + 最佳评级）。
- 解锁条件：通关对应星球 / 收集全部晶体。
- 数据来自 `Save`。

**关联**：依赖 `Save`、`SongDB`；被 HOME 菜单打开。
**优先级**：P1。

---

### 3.8 资源经济（Economy）★ P2

**现状**：`resBar()` 显示三种资源（紫 12 / 青 8 / 金 3），纯静态。

**设计**：
- 三资源语义：**能量 Energy（紫）** = 收集晶体累积；**音核 Shard（青）** = 通关奖励；**音符 Note（金）** = 踩点连击奖励。
- 用途：解锁新曲（消耗音核）、修复传送门（消耗能量）、图鉴补全（消耗音符）。
- 先在 BASE 结算页做"结算 → 入库"闭环，其余消耗项 M3 再铺。

**关联**：依赖 `Save`；影响 `Codex`/`SongDB` 解锁。
**优先级**：P2。

### 3.9 数值与手感总表（Tuning Sheet）★ P0

> 把散落在各节、乃至代码里的手感数字**集中成一张可对照调参表**。凡标"现值"的均来自当前代码锚点，可直接对上；凡标"建议"的为 M1 首版取值，**落地后以实测帧率与手感为准微调**。

| 参数 | 符号 | 现值 / 建议 | 锚点 | 备注 |
|---|---|---|---|---|
| 前进速度（主轴） | `SPEED_F` | 建议 **4.5 u/s** | 待建 | 出生点→desert 环门 ≈ 82.5u ⇒ 直线 ≈18.3s |
| 横移速度 | `SPEED_S` | 建议 **1.6 u/s** | 待建 | 约为主速的 1/3，避免破坏舞台式构图 |
| 冲刺倍率 | `SPRINT` | 建议 **1.6×**，耗能 | 待建 | 踩强拍触发可免费 |
| 跳跃初速 | `V0` | 现值 **6.0**（doJump） | 2335 | 踩点建议 **7.2**（+20%） |
| 重力 | `G` | 现值 **18 u/s²** | 2484 | 滞空 ≈ 2·6/18 = **0.67s**；跳高 ≈ `V0²/2G` ≈ **1.0u** |
| 落地缓冲 | `T_LAND` | 建议 **0.15 s** | 待建 | `poseHero` 增 `land` 分支 |
| 拍点窗口 | `W_BEAT` | 建议 **±0.09 s** | 待建 | `bpm=118` ⇒ 单拍 508ms，窗口占 35% |
| BPM | `bpm` | 现值 **118** | 2339 | 由 `SongDB.cur.bpm` 驱动 |
| 强弱拍 | — | kick 每拍 / hat 隔拍 | 2366 | `beatCount % 2 === 1` 出 hat |
| 吸附半径 | `R_COLLECT` | 建议 **2.5 u** | 待建 | 约角色身高 1.5u 的 1.7 倍 |
| 吸附缓动时长 | `T_COLLECT` | 建议 **0.25 s** | 待建 | ease-out，飞向角色胸口 |
| 传送判定半径 | `R_PORTAL` | 建议 **3.0 u** | 待建 | 约为门半径 `r=6.4`（1661）的一半 |
| 相机微跟随系数 | `k` | 建议 **0.8**（指数平滑） | 待建 | 方案 B 用，位移 ≤ **3% 视口** |
| 场景过渡白闪 | `T_FADE` | 建议 **0.35 s** | 待建 | 覆盖层遮罩，不动相机 |
| 主混音增益 | `master.gain` | 现值 **0.14** | 2344 | SFX 另开分总线（见 §6.6） |

**手感黄金律（验收时逐条对照）**

1. **输入零延迟**：`Input.poll()` 在每帧最前（§6.3），动作当帧生效，不做缓冲。
2. **跳跃可预读**：落地前 0.1s 内按跳 → 落地瞬间自动起跳（coyote time / jump buffer），跳跃手感的关键。
3. **速度有起停缓动**：前进速度 0.12s 内线性升到 `SPEED_F`，松手 0.10s 内降到 0；**但横移保持硬响应**（横移要跟手）。
4. **姿态与位移解耦**：`poseHero` 只改 y 与四肢，**x/z 一律由 `PlayerController` 写**（避免再现"姿态覆盖位移"的历史 bug，见 §0.2 记录）。
5. **节拍反馈必可感知**：踩点成功时"波纹 + kick 重音"同帧出现；未踩点则**什么都不给**（负反馈靠"没有正反馈"体现，不扣分）。

**关联**：约束 `PlayerController`(#2)、`BeatClock`(#6)、`Portal`(#8)、`CameraRig`(#10)。
**优先级**：P0——数值表不定稿，M1 的"手感验收"无从谈起。

### 4.3 流程状态机（GameState）

```
Boot ──► Title(HOME) ──选曲──► SongSelect ──开始旅程──► Play
                    ▲                                      │
                    │                                  通关/退出
                    │                                      ▼
                    └────────── Codex ◄── Result(BASE) ◄───┘
                                    ▲
                                    └─ Settings / PlanetCodex（覆盖层，不离开 Title）
```

- `Play` 的 `scene` ∈ {desert, cave}。
- `Result` 复用 BASE 场景（它本就是"基地"），在基地里做结算。
- `Codex`/`Settings` 为覆盖层，底层场景不销毁。

### 4.4 关卡内空间结构（以 DESERT 为例）

```
  出生点(近景沙地) ──◆──◆────◆──────────► 山顶(远景高地 + 传送门)
                    shard1 shard2 shard3        summit + portal
  ────────────────────────────────────────────────────────────
  主线：沿 z 轴负方向前进约 60~80u；三晶体沿路径等距分布；
        山顶设传送门，集齐后亮起。
```

- 晶体位置走 `dseq` 生成，**不占用 `rnd()`**。
- 山顶高度用现有 `dh()` 采样，确保贴合既有地形（不改地形）。

### 4.5 通关条件与结算

| 条件 | 判定 | 反馈 |
|---|---|---|
| 集齐晶体 | `collected >= need` | 传送门 `charged` |
| 激活传送/到达目标点 | 进入判定圈 | 白闪 → 切场景 → `Result` |
| （P2）评级 | 踩点完美率 / 最高连击 | S/A/B/C + 战绩卡 |

### 4.6 DESERT 晴天星 · 跑酷关详细设计（M1 第一个要打通的关）★ P0

**先量后设：对 `dh(0,z)` 沿前进轴实测高度剖面**（脚本复算 1554 行公式）：

| z | 0 | −20 | −28 | −40 | −52 | **−64** | −76 | −84 | −96 |
|---|---|---|---|---|---|---|---|---|---|
| `dh(0,z)` | 0.76 | 0.40 | 0.00 | −1.01 | −2.30 | **−3.19** | −2.15 | −0.77 | **+1.36** |
| 段位 | 起跑 | | 谷口 | | | **谷底** | 冲顶 | 门区 | **远端高丘** |

> **重要修正（推翻 §4.4 的"一路爬上山顶"）**：desert 实际是 **下坡冲进沙谷（z≈−64 最低，落差 ≈4u）→ 再爬上远端高丘** 的"V 形"结构。因此"到达山顶"这一任务名应改判为 **"抵达远端高丘"**，判定点落在 `z ≈ −92~−96`（地面回升到 +1.36 处），而非谷底。

**三段式关卡结构（主线沿 z 负方向 ≈ 82.5u）**

```
 出生(0.6,-1.5) y0.77 ──► 缓降 ──► 谷口(-28) y0.00 ──► 陡降进谷 ──► 谷底(-64) y-3.19
        │                                                                            │
     晶体①(2.0,-22)                                        晶体②(-3.5,-46)     晶体③(3.5,-70)
        │                                                                            ▼
        └──────────────────────────────── 爬上高丘 ──► 门区(-84) ──► 高丘判定(-92~-96) ──► 激活传送
```

| 段落 | z 区间 | 高差 | 玩法意图 | 布置 |
|---|---|---|---|---|
| **① 起跑段** | 0 → −28 | 0.76 → 0.00（缓降） | 无压力教学：跑 + 第一次吸附 | 晶体① `(2.0, −22, dh=0.30)` |
| **② 沙谷段** | −28 → −64 | 0.00 → −3.19（最陡） | 节奏加密：下坡冲刺 + 横移找晶 | 晶体② `(−3.5, −46, dh=−1.54)` |
| **③ 冲顶段** | −64 → −84 | −3.19 → −0.77（上坡） | 收束：最后一颗 → 门亮 | 晶体③ `(3.5, −70, dh=−2.82)` |

- 晶体悬浮高度 = `dh(x,z) + 1.2u`（贴地采样，**不改地形**）；位置走 `dseq(0xC011)`，零漂移。
- 每个晶体正前方 6~8u 处的地形起伏即天然"跳跃点"，踩点起跳有加分（§3.2）。

**⚠️ 环门的高度陷阱（必须处理）**：现有 `ringGate` 被放在 `y = dh(−1.2,−84) + 15.5 = 14.6`（1662），是**为定帧构图服务的天空远景**（"地平线上的小石环"），而 `beam` 在 `y = dh+3`（1672）——**门本体悬在地面上方 15.5u，玩家根本够不到**。红线 2 禁止移动既有地物，故给出两个不改定帧的解法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **（推荐）落地激活台** | 在门正下方地面新增一个**确定性 helper**（如 `portalPad()`：发光圆台 + 判定圈），玩家跑上去即激活；天空中的环门作为"门开了"的远景呼应 | 新增 1 个对象（走 dseq/纯参数，零漂移） |
| 平面判定 | 判定只取 `(x,z)` 平面距离、**忽略 y**，玩家站到门下方即激活 | 无新增，但"在悬空门下激活"的观感略怪 |

**关联**：`PlayerController`(#2)、`Collectible`(#3)、`Portal`(#8)、`TaskSystem`(#4)。
**优先级**：P0（M1 的唯一关卡目标）。

### 4.7 CAVE 夜曲星 · 探索关详细设计 ★ P1

**现状可直接复用的"关卡脊柱"**：buildCave 已有一条**青蓝发光地砖路径**（1895–1902），自出生点向洞深处延伸 8 块，坐标 `z = −3.2 − (i+1)·4.0`、`x = −1.75 + sin(i·1.7)·0.8`（即 z ≈ −7.2 … −35.2）。这本身就是天然的**引导路标**——昏暗洞穴里靠它寻路，无需新造导航。

| 要素 | 既有资产 | 玩法定位 |
|---|---|---|
| 出生点 | `(−1.75, ·, −3.2)`（1907–1908） | 起点 |
| 引导路径 | 8 块发光地砖（1895） | 主脊，指引入洞 |
| 大晶簇地标 | 品红 `(−11,−20)` + 橙红 `(10.5,−14)`（1880–1885） | 采集点①②（左右各一，逼玩家横移"离开安全路径"） |
| 天光柱 | `beam` at `(−3.4, ·, −42)`（1814）+ glowSprite（1824） | 终点地标 + 传送落点 |
| 倒挂巨晶 | `hb1(−9.5,19.5,−38,h7.2)` / `hb2(5.5,18.5,−50,h6)` | 视觉锚点（不参与判定） |

- **采集点③** 建议新增于天光柱正下方 `(−3.4, chh, −42)`，与前两点构成"左—右—中"三角，收束探索动线。
- **传送落点**：天光柱即视觉上的"出口光"，判定圈取 `(−3.4, ·, −42)` 平面半径 3.0u。
- **昏暗寻路**：雾 `FogExp2 0.0098`（既有）已提供压迫感；地砖 + 晶簇 glow 是仅有的导航光——**不要再加全局照明**，否则探索感消失。
- **性能**：cave 已 1725 calls（最紧张）。新增采集点**必须复用既有 `gemCluster` 几何或单几何合并**，严禁逐个新建 mesh。

**关联**：与 desert 共用同一套 `PlayerController/Collectible/Portal`，仅 `LevelDef` 不同。

### 6.6 音频设计（Audio Design）★ P1

**现状（代码事实）**：`initAudio`(2340) 建 `master.gain = 0.14`；`kick`(2348) 正弦 140→46Hz、0.22s 包络；`hat`(2355) 白噪 + 6.4kHz 高通、0.12s；`scheduleAudio`(2363) 用 0.18s 前瞻循环排拍，**每拍 kick、隔拍 hat**（2366），`bpm` 常量 118。

**设计**：

1. **总线拆分**（现在的 `master` 只够节拍，加旋律会糊）：
   `master ← musicBus(旋律+节拍) / sfxBus(音效)`，各自限幅后再汇入 `master`。
2. **节拍骨架**：由 `SongDB.cur.bpm` 驱动（替换常量 118）；每拍 `Bus.emit('beat',{t,index,strong})`，强拍=kick。
3. **每星球一条旋律动机**（2~4 音循环，复用 `Oscillator`，`AudioMelody` 模块）——这是"真的像一首歌"的关键，也是"音乐即世界"支柱 P1 的载体：

| 星球 | 情绪 | 建议调式/动机 | 建议 BPM* |
|---|---|---|---|
| 晴天星 | 明亮·奔跑 | 大调五声，上行三音动机 | ≈ 76 |
| 夜曲星 | 幽暗·探索 | 自然小调，级进下行 | ≈ 88 |
| 稻香星 | 温暖·归家 | 宫调五声，级进 + 八度跳 | ≈ 124 |

> \* BPM 为**占位建议值**，最终以正式版音乐为准；动机需与关卡机关密度正相关（BPM 越高，机关越密）。

4. **SFX 清单**（全部走 `sfxBus`，不随 bpm 变速）：

| 事件 | 音色 | 触发点 |
|---|---|---|
| `collect` | 上行琶音（3 音，随连击升 key） | Collectible 吸附完成 |
| `jump` / `land` | 短滑音 / 闷响 | doJump / 落地 |
| `beatPerfect` | 脆响（高音短促） | 踩点窗口命中 |
| `portalCharged` | 和弦上扬 | 集齐晶体（§3.4 charged） |
| `portalGo` | riser 扫频 | 进入判定圈切换场景 |
| `uiClick` / `uiBack` | 轻点 / 低音回退 | 所有按钮 |

5. **无障碍与静音**：提供音量/静音开关（§5.5 设置）；音频启动仍依赖用户手势——**已解决**（`pointerdown` 2378 已触发 `initAudio`）。

**关联**：`BeatClock`(#6)、`HUD`(#7)、`VFX`(#12)。**优先级**：P1。

```js
  init: function(k){ /* 读 LEVELS[k].path 与出生点；存 ground 高度函数引用 */ },
  update: function(dt){
    /* 1) 速度缓动 → 位移 x/z（只改 x/z）
       2) ground = level.ground(x,z)（dh/gh/fh/chh）
       3) 贴地：baseY = ground；跳跃时 + jump.y
       4) 姿态：poseHero(hero, mode, T, jump.y)  // poseHero 只管 y 与四肢 */
  }
};

var Collectible = {
  register: function(mesh, ctype){ mesh.userData.collectible = true; mesh.userData.ctype = ctype; },
  update: function(dt){ /* 距离 < R_COLLECT → 0.25s 吸附缓动 → emit('collect') */ }
};

var BeatClock = {
  onBeat: function(fn){ Bus.on('beat', fn); },
  inWindow: function(){ /* |now - lastBeatTime| <= W_BEAT */ return false; }
}; /* 包装 scheduleAudio(2363)，在 kick 时刻 Bus.emit('beat',…) */

var Portal   = { set: function(k){}, update: function(dt){ /* dormant→charged→activated */ } };
var TaskSystem = { progress: function(id, n){ /* → HUD 重渲染该行 */ },
                   isClear: function(){ return false; } };
var VFX = { burst: function(pos, type){}, ripple: function(pos){}, flash: function(t){} };
```

**接入落点（对照 §6.3 每帧顺序）**

```js
function loop(now){
  Input.poll();
  BeatClock.update();
  PlayerController.update(dt);
  Collectible.update(dt);
  Portal.update(dt);
  /* —— 以下为既有逻辑，保持不动 —— */
  updateScene(cur, dt);
  HUD.sync();
}
```

## §8 关联与优先级总览（一图收束）

### 8.1 模块 → 玩法 → 关卡 关联矩阵

| 模块 \ 提供 | 核心玩法 | 主要机制 | 关卡落地 |
|---|---|---|---|
| `Input` | ✔ 操作入口 | — | 全关卡 |
| `PlayerController` | ✔ 跑跳 | 移动机制 | DESERT/CAVE |
| `BeatClock` | ✔ 节拍 | 音乐机制 | 全关卡 |
| `Collectible` | ✔ 收集 | 收集机制 | DESERT/CAVE |
| `Portal` | — | 传送机制 | DESERT/CAVE |
| `TaskSystem` | ✔ 目标 | 任务机制 | 全关卡 |
| `GameState` | — | — | 流程骨架 |
| `SongDB`/`Codex`/`Economy`/`Save` | — | 歌曲/图鉴/经济 | HOME/BASE |

### 8.2 优先级排序理由

1. **先有"能玩"**：`Input`→`PlayerController`→`Collectible` 三步构成最小可玩动作链，缺一不可，故全 P0。
2. **再有"目标"**：`TaskSystem` + `HUD` 让玩家知道"要干什么"，否则收集无意义。
3. **再有"节拍"**：`BeatClock` 是支柱 P1/P2 的载体，但它可以后插——M1 先让跑跳收成立，节拍作为增益叠加。
4. **然后"收束与串联"**：`Portal` + `GameState` 把单关串成流程。
5. **最后"内容与留存"**：曲库/图鉴/经济/存档/演出，决定这游戏"像不像成品"。

### 8.3 一句话推进顺序

> **先让晴天星"跑起来、收得到"（M1），再让三颗星"串起来"（M2），最后让整颗星球"留下来"（M3）。**
