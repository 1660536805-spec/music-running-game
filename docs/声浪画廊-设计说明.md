# 声浪画廊 · 设计说明（P8）

> 赛道两侧的「专辑封面」与「声浪诗行」—— 把正在播的那张专辑、正在唱的那句词，
> 变成跑酷赛道旁**可看、随之呼吸**的实体。
> 实现位置：`声浪星球.html` 内 `SoundGallery` 模块（单文件、零构建、无新增资源）。

---

## 0. 一句话主张

承接《游戏与流行音乐脱节》简报的结论：**音乐不能只停在氛围层**。
本模块不新增玩法规则，但把「音乐的身份」从「背景音」提到「与谱面障碍同屏、同拍的第二坐标系」——
玩家一边躲闸门，一边看得见这张专辑在转、看得见这一句词在亮，且二者都由**同一根音乐时钟**驱动。

---

## 1. 空间布局总表

以英雄（`hero`）为原点，**每帧随 `hero.position.z` 刚性平移** —— 因此两板恒定停在视野左右，不会飞出画面。
相机（追尾机位）位于 `hero + (0, 1.55, 4.90)`，俯视 `−z`。

| | 左 · 浮空唱片台 | 右 · 声浪诗行 |
|---|---|---|
| 锚点 | `(−4.25, 1.80, hero.z − 1.15)` | `(+4.25, 1.95, hero.z − 1.15)` |
| 距赛道中心 | 4.25 m（赛道半宽 1.75 ⇒ 轨外 2.50 m） | 4.25 m（轨外 2.50 m） |
| 朝向 yaw | **+0.50 rad（≈ 28.6°）** | **−0.52 rad（≈ −29.8°）** |
| 本体尺寸 | 封面 **2.15 m 见方**；黑胶盘 r = 0.62 m；辉光 3.48 m；边框 2.31 m | 行面 **3.00 × 0.375 m**；**7 行位**；顶栏 2.60 × 0.28 m |
| 行距 / 纵深 | — | DY = **0.42 m**，DZ = **0.10 m**（越远越向后收） |
| 追尾机位屏幕落点 | 画面左侧 ≈ **屏幕左 1/3** 处 | 画面右侧 ≈ **屏幕右 1/3** 处（P8+ 内收后右缘留白） |
| 距相机 | ≈ 7.6 m | ≈ 7.7 m（首行） |

> **P8+ 视觉打磨**：两板各**向内收 0.35 m**（±4.60 / ±4.70 → ±4.25）、封面 **1.90 → 2.15 m** ——
> 前者给画框左右留白（原追尾视图右板贴屏右缘），后者强化"浮空实体"体积感；
> `W/H` 保持 `3.00/0.375`（= 画布 `1024:128` 的 8.0 宽高比，缩放不压字），**yaw / 存在感策略不变**。

**为什么是「八字环抱」而不是正对镜头**：yaw 取 ±0.5 rad 而非正对相机的 ±0.65 rad，
使两板各自保留约 9° 的侧向余量 —— 既保证文字/封面可读，又保留「立体展示」的透视感
（正对镜头会退化成平面贴片，丢掉浮空体积）。二者共同构成向赛道中心收拢的"八字"。

## 2. 左 · 浮空唱片台（AlbumFloat）

### 2.1 构成（4 个 draw call）

| 构件 | 说明 |
|---|---|
| 辉光 `glowMesh` | 3.48 m 加色面片，颜色 = **当前段落主题色**，透明度随节拍/同调/进程变化 |
| 黑胶盘 `vinylMesh` | r = 0.62 m，圆心在局部 `x = −0.72` ⇒ **向左探出封面 ≈ 0.27 m**（复刻"唱片从封套抽出"） |
| 封面 `albumMesh` | 2.15 m，512² 程序化 canvas（渐变底 + 径向辉光 + 波形条 + 曲名/艺人 + 内描边 + 角标） |
| 边框 `frameMesh` | 2.31 m 加色描边，颜色 = 段落主题色 |

> 全套 **程序化几何 + canvas 现画**，零新增图片资源，遵守项目「禁 PBR / 照片纹理」规范。

### 2.2 动态分解

| 动作 | 公式 | 频率 / 幅度 |
|---|---|---|
| 浮沉 | `y += sin(T · 0.90) · 0.10` | 周期 ≈ 7.0 s，幅度 **±0.10 m** |
| 横漂 | `x += sin(T · 0.52) · 0.10` | 周期 ≈ 12.1 s，幅度 ±0.10 m —— 与浮沉不同频 ⇒ 呈利萨如"悬浮"轨迹 |
| 基础偏航 | `+0.50` | ±28.6° |
| 微偏航 | `+ sin(T · 0.42) · 0.055` | **±3.2°**，周期 ≈ 15 s |
| 微侧倾 roll | `sin(T · 0.63) · 0.018` | ±1.0° |
| 微俯仰 pitch | `sin(T · 0.37) · 0.020 − prog · 0.06` | ±1.1°，并随进程**缓慢前倾至 −3.4°** |
| 黑胶自转 | `−(songT / (2·spb)) · 2π − resoSpan · 6.0` | **2 拍一圈**，由谱面 `spb` 推导 ⇒ 与音乐严格锁相 |
| 整体缩放 | `(1 + 0.035·beat + 0.05·reso) · lensScale` | 节拍呼吸 +3.5% |

> **关键**：黑胶转角不是"每秒转多少"的自由动画，而是**由 `songT` 直接求值** —— 暂停、seek、重玩都自动对齐，永不漂移。

## 3. 右 · 声浪诗行（LyricScroll）

### 3.1 逐句滚动算法（QQ 音乐式"连续位移"，非跳字）

设 7 个行位 `i = 0..6`，中心 `c0 = 3`。

```
idx  = max{ j | lines[j].t ≤ songT }                 // 当前行
frac = (songT − lines[idx].t) / (lines[idx+1].t − lines[idx].t)   // 行内进度 ∈ [0,1]

offset_i = (c0 − i) + frac − 0.5                     // >0 = 过往（上浮），<0 = 未唱（下沉）
y_i      = offset_i · DY                             // DY = 0.42 m
z_i      = −|offset_i| · DZ                          // DZ = 0.10 m（越远越向后收 ⇒ 纵深视差）
scale_i  = 1 − min(0.34, |offset_i| · 0.105)
           · (当前行再 × (1 + 0.055 · beat))
alpha_i  = clamp(1 − |offset_i| · 0.30, 0.05, 1)
           · (当前行 1.0 / 其余 0.92)
```

- **`− 0.5` 的作用**：令当前行在 `frac = 0.5` 时正落于视觉焦点，
  行切换瞬间前后位置**连续**（不发生跳动）—— 这是"逐句滚动"与"逐句闪现"的分界线。
- 行文只有**当前行**带段落色强调条 + 白色发光（`shadowBlur 24`）；其余行 60% 灰蓝。
- 字号：当前行 **70 px** / 其余 **56 px**（canvas 1024×128）；超宽自动降号至 30 px 兜底。
- **行位复用**：只有当某行位的"文本或高亮态"发生变化时才重绘 canvas（每乐句至多 2 次）
  ⇒ **零 per-frame canvas 写入**、7 个 draw call 恒定。

### 3.2 顶栏

`声浪诗行　SOUNDWAVE VERSE · 副歌` —— 右侧标签 = **当前段落**，颜色随段落迁移。
它把"这首歌走到哪了"直接写在画面上。

## 4. 与音乐 / 游戏进程的耦合总表

| 驱动源 | 取自 | 作用 |
|---|---|---|
| **节拍** | `Bus 'beat'`（`BeatClock.onKick` / causeway 谱面 kick） | 封面 +3.5% 呼吸；辉光增强；**当前词行脉冲放大**；边框加亮 |
| **段落** | `Track.section.kind` | 主题色平滑迁移（2.2 /s 插值）到 **辉光 / 边框 / 封面配色 / 词行强调条 / 顶栏标签** |
| **同调（长按）** | `CWInput.resonating` | 黑胶**额外加速外旋**（+6 rad/s 累积）；封面外推 +5%、偏航外张 3.4°；辉光拉满 |
| **判定** | `CWScore.miss` 增量 | 命中 ⇒ 当前词行白闪；**Miss ⇒ 整条诗行短促失焦**（0.45 s 内透明度 ×0.55，黑胶同时压暗）—— 让"乐声踉跄"看得见 |
| **进程** | `prog = songT / duration` | 辉光基线 0.18 → 0.32；封面俯仰前倾至 −3.4°；越到后段越亮越外张 |
| **镜头** | `Lens.cur` | 见 §5 |

### 段落主题色

| 段落 | 前奏 | 主歌 | 预副歌 | 副歌 | 桥段 | 高潮 | 终章 |
|---|---|---|---|---|---|---|---|
| kind | `intro` | `verse` | `preChorus` | `chorus` | `bridge` | `climax` | `outro` |
| 颜色 | `#18E0FF` 青 | `#59C8E8` 天蓝 | `#9E5EE8` 紫 | `#FF4FD8` 洋红 | `#8CFFC8` 薄荷 | `#FFA62B` 琥珀 | `#A78BEA` 淡紫 |

> 主题色不是装饰：`chorus` 洋红即赛道 Hi 层色、`bridge` 薄荷即赛道加速色 ——
> **听到副歌，就看到洋红**，与谱面机制同源同色。

## 5. 镜头存在感策略（"不挡镜"与"尽量常驻"的折中）

赛道镜头系统（Lens）每乐句切换一次机位。画廊按机位给出**三重存在感**（透明度 / 缩放 / 内收）：

| 机位 | 透明度 | 缩放 | 内收 | 理由 |
|---|---|---|---|---|
| `chase` 追尾 | **1.00** | 1.00 | 1.00 | 主视图，全显 |
| `overhead` 俯视 | 0.85 | 0.95 | 0.90 | 略退为背景 |
| `onboard` 贴身 | 0.75 | **0.60** | **0.52** | 特写幅度大，整体**内收 + 缩小**以免顶出画框 |
| `lateral` / `drift` 侧视/漂移 | **0** | 1.00 | 1.00 | 相机贴到赛道右缘，词板会顶满画面 ⇒ **整组让镜**（刻意为之：侧机位是给英雄的运镜） |

所有存在感参数以 `dt · 4.5` 插值（≈0.22 s 过渡），与镜头 0.18 s 切换时长匹配，无突现突隐。

> 实测：默认曲 `rapGalactic` 的镜头分布 = 俯视 35% / 侧视 30% / 贴身 23%，
> 其余曲目（超频长阶、银翼回响）侧视+漂移仅 ~12%。侧视让镜是该机位的美学选择。

## 6. 歌词来源（诚实口径）

内置 4 首曲目**全部是器乐**（无原唱词），因此：

1. **优先**：若谱面携带 `chart.lyrics`（LRC 式 `[{t, text, kind?}]`），**直接用真词**
   —— 供未来带词曲目 / 用户上传歌使用，消费端零改动。
2. **兜底**：按谱面结构生成「声浪诗行」—— 每个**乐句**一句（8 小节以上乐段再按 4 小节细分），
   文本取自按曲目主题撰写的唱词库（`SoundGallery.VERSE`）：
   - `superweave` 超频长阶 / `song2` 银翼回响 / `rapGalactic` Galactic Rap / `rapChristmas` Christmas Rap
   - 未登记的曲目走 `VERSE_KIND` 段落级兜底句。

> 面板顶栏刻意标注 `SOUNDWAVE VERSE`（而非 "LYRICS"）—— 生成词不冒充实词。

实测（`rapGalactic`，141 s / 69 小节 / 9 段）：生成 **17 句**，平均 8.3 s 一句。

## 7. 技术实现与红线

| 项 | 结论 |
|---|---|
| **定帧保护** | `mount()` 内 `if (FREEZE) return`（照抄 `Obstacle` / `MelodyLane`）⇒ 定帧 children / calls / tris **完全不变** |
| **实测定帧基线** | `calls = 147`、`tris = 5800`、`heroC = [0.509, 0.537]` —— **逐位未变**（P8+ 打磨后复跑 `causeway.js` / `quadcheck.js` 仍 PASS） |
| **P8+ 视觉打磨** | 两板内收 0.35 m + 封面 1.90→2.15 ⇒ 画框留白与体积感；**只改 `ALB/LYR` 常量，`mount()` 未动 ⇒ 定帧基线逐位未变** |
| **四场景影响** | 对象只进 `SCN.causeway.scene` ⇒ home/desert/cave/base 的 calls 与 heroC **逐位不变** |
| **draw call 增量** | 非定帧 causeway：**147 → 156**（+9）；album 4 + lyric 7（±顶栏 1） |
| **tris 增量** | 5800 → 5990（+190） |
| **per-frame 开销** | 仅写 `position / rotation / scale / material.opacity / color`；**零几何重建、零 canvas 重绘**（canvas 只在文本或高亮态变化时重绘） |
| **随机流纪律** | 封面波形用确定性公式（`sin/cos`），**不消耗任何全局 `rnd()` / `dseq()`** ⇒ 不扰动既有随机序列 |
| **渲染层** | 材质 `depthWrite:false + depthTest:false + fog:false`，`renderOrder` 9–30 ⇒ 呈"浮空全息"且始终可读 |
| **接线（5 处）** | `loop` 内 `!FREEZE` 块 / `M1.enter` causeway 分支 / `Chart._resetConsumers` / `__cwSeek` / `__info` |

### 调试 / 门禁钩子

- `window.__Gallery` —— 模块本体
- `window.__info().cw.gallery` —— `{mounted, lines, idx, text, kind, fade, scale, gather, pulse, reso, album:{x,y,yaw,size}, lyric:{x,y,yaw,slots,dy}}`
- `window.__cwSeek(t)` —— 跳到任意音乐时刻验证逐句滚动
- `tools/shot_gallery.js <t1,t2,…>` —— 指定时刻出图（1280×720）

## 9. 后续可做

- **真词接入**：给谱面加 `lyrics` 字段即可启用真词滚动（已有实现，无需改代码）。
- **逐字卡拉OK**：把行 canvas 改为按 `frac` 裁切的双层描边，可实现逐字染色。
- **上传歌**：`ChartBuilder` 生成的运行时谱面同样走 `VERSE_KIND` 兜底 ⇒ 上传任意歌即有声浪诗行。
- **封面来源**：可把用户上传音频的 ID3 封面解出，替换程序化封面（当前为纯程序化，零版权风险）。
