## §0 摘要与主张

### 0.1 产品主张（Thesis）

> **「把流行乐的时间结构，翻译成一条要你回答的跑道。」**

备选金句（用于答辩不同场景）：

- **「换一首歌，换的不是曲包，是玩法本身。」** —— 正面回答机制层的唯一判据。
- **「别人让你跟着歌打拍子，我们让你在歌里跑完整首歌的情绪。」** —— 面向观众的通俗版。

**为什么是这一句**：《游戏与流行音乐脱节》分析给出的硬判据只有一条——*"把这首歌换掉，玩法会不会变？"*（`docs/游戏与流行音乐脱节-分析brief.md:11`）。主张必须敢正面回答"**会变**"，并且把差异锁定在**时间结构**（而非横向位移）上——这恰是《超频长阶》单赛道已经建立的骨架：分赛道问"往哪躲"，它问"**下一拍会发生什么**"（`docs/声浪星球-关卡设计-超频长阶.md:53-56`）。

### 0.2 痛点（15 秒版）

1. 市面上的音游几乎都停在"**类型层**"——换歌换的是**内容**，不是**规则**（Beat Saber、世界计划）。
2. 流行乐被压在"**氛围层**"（换歌只换情绪）——因为它拿不到"**可改造、可交互**"的权利。
3. 本项目早期也踩过同一个坑：玩家**「在跑酷但没在听歌」**——横向换道把注意力从时间轴抢走了（`超频长阶.md:33`）。

### 0.3 差异化钩子（一眼可演示）

**误导体（Decoy）**：一个"看着像障碍、其实无害"的物体，它被放在**非 onset** 位置。**凭视觉反应的人吃亏，跟着音乐呼吸的人受益**——用机制而非说教筛选玩家行为（`超频长阶.md:150-161`）。这是全文最容易被评委记住、也最容易现场演示的一个装置。

## §1 背景与问题

### 1.1 音乐有三层，判据只有一个

判断任何一款用音乐的游戏，只需问一句：「**把这首歌换掉，玩法会不会变？**」（`brief:11`）

| 层 | 定义 | 代表作品 | 流行乐的位置 |
|---|---|---|---|
| **氛围层** | 换歌只换情绪，玩法不变 | GTA 电台 / FIFA、NBA 2K 歌单 / 2077 | 最舒服、最普遍 |
| **类型层** | 音乐是玩法主轴，但"这首歌"与"那首歌"机制上可互换 | Guitar Hero / Beat Saber / 世界计划 | 大量存在 |
| **机制层** | **音乐的时间结构直接决定操作**，换歌则玩法本身改变 | Patapon / Crypt of the NecroDancer / Hi-Fi Rush | **几乎看不到主流流行乐** |

一个方向性旁证：据行业指南估算，授权曲目只出现在约 **28%** 的 3A 作品中，其余七成靠自有作曲（`brief:17`）。**越主流的音乐，越只能待在越低的两层。**

### 1.2 两道串联的锁

「游戏与音乐关联薄弱」这个判断，一半对、一半错。错的一半：需求侧从不缺意愿——Fortnite 的虚拟演唱会能拿下千万级并发（`brief:22`）。对的一半：**音乐几乎总是停在「听」的位置，极少获得「决定怎么玩」的资格**。拦住它的是两道串联的锁：

- **锁 A · 认知 × 流程**：音乐在多数项目里被归入「音频资产」而非「玩法提案」，立项时没被邀请进玩法会议 ⇒ 流程里**没有让音乐参与玩法设计的接口**（`brief:28-30`）。
- **锁 B · 版权结构**：一首流行歌的权利是碎的（录音母带权 + 词曲同步权分属不同主体），且大量采用**限时授权** ⇒ 你买得到"一次性、背景式、有时限"的播放权，买不到"**可改造、可长期、可实时交互**"的权利——而后者恰是机制层用法的前提（`brief:35-37`）。

> **最尖锐的一处错位**：技术上最易做节拍分析的，恰是节拍规整的流行/电子；版权上最贵、最受限的，也恰是流行乐。**技术可行区与版权可行区几乎不重叠**——这是脱节最硬的墙（`brief:44`）。

### 1.3 本项目的历史包袱与转机

- 早期愿景文档《游戏总开发文档》写的是"上传任意歌 → 自动生成关卡"，但它**首行就声明自己是"愿景层/旧原型层"，当前单文件原型未实现**该能力。
- 转机在于：项目把"跑酷"这一**公共游戏形式**与"音乐数据"这一**私人数据源**相乘，得到"只属于我的关卡"的独创性公式（`声浪星球-游戏总开发文档.md:86`）；并用《超频长阶》把"**取消分赛道，把决策维度还给时间**"真正做成了可玩的东西。
- **本设计要做的，就是把这条已经跑通的单赛道骨架，向"真实流行乐"推进一格。**

## §2 产品主张与设计原则

### 2.1 主张展开

主流音游是"**类型层**"：一套判定系统套不同曲包，换歌不换规则。我们要做的是"**机制层**"：**音乐的段落结构、能量起伏、旋律走向，直接决定玩家要回答什么问题**。由此，"换歌即换关"不再是一句宣传语，而是一个可被验证的产品事实。

### 2.2 六条设计原则

| # | 原则 | 界定「什么才算体现音乐性」 | 明确「不做什么」 |
|---|---|---|---|
| **P1** | **时间即唯一决策维度** | 任何玩法都必须能回答"它对应音乐的哪一段 / 哪一拍" | 禁止重新引入横向换道或空间安全区（会稀释"听"的注意力，`超频长阶.md:63-68`） |
| **P2** | **结构必须可感知，而非可解释** | 玩家在**不看 HUD**时也能感到"副歌来了 / Drop 到了 / 要收尾了" | 禁止把音乐结构做成"只写在文档里的映射表"，却没有听/视/操反馈 |
| **P3** | **只奖励理解，不惩罚失手** | 加分项（预判 / 同调 / 旋律加成）永不倒扣 | 不因"没听懂"归零连击（沿用 `CWAnt` 押错 = ×1.0 的既有哲学，`声浪星球.html:3595`） |
| **P4** | **判定口径跨歌一致** | 同一份谱面 schema 在不同 BPM 下体感难度可控 | 不允许"判定窗口随歌漂移"而不做 BPM 归一 |
| **P5** | **真实歌 = 数据源，不是资源包** | 只消费分析产物（`Analysis → Chart`），运行时判定层零特判 | 不为某首歌写专属硬编码玩法分支 |
| **P6** | **表现层与逻辑层解耦，守住零漂移** | 玩法逻辑包在 `if(!FREEZE)` 内，新增视觉走 `dseq(seed)` | 不因"自动生成"改动四场景几何（踩视觉零漂移红线 R1） |

> 一句话压缩：**P1 定维度、P2 定感知、P3 定宽容、P4 定公平、P5 定可扩展、P6 定工程红线。**

## §3 玩法内核：单赛道范式

### 3.1 为什么取消分赛道

单赛道不是"少了一条路"，而是把**决策维度从空间搬回时间**。

| 分赛道（空间决策）的问题 | 单赛道（时间决策）的收益 |
|---|---|
| 横向位移与音乐的时间结构无关 | 空间被固定 ⇒ 注意力 100% 投向时间轴 |
| 多条道产生"安全区"，可长期待在同一道躲避 | 无安全区 ⇒ 每次规避都必须**回答音乐的提问** |
| 换道语义是"位移" | 升降语义是"**节奏应答**"（1 输入 = 1 状态翻转） |
| 视角固定、与音乐无关 | 视角成为**音乐信息的编码器** |

（来源：`超频长阶.md:61-68`）

### 3.2 操作范式：两种状态 + 一种姿态

| 操作 | 语义 | 移动端 | 键盘 | 判定意义 |
|---|---|---|---|---|
| **升 Lift** | 切到 Hi 悬浮层 | 上滑 / 上半屏轻点 | `↑` / `W` | 规避低位闸门 |
| **降 Dive** | 切到 Lo 贴地层 | 下滑 / 下半屏轻点 | `↓` / `S` | 规避高位闸门 |
| **同调 Resonate** | 长按贴合旋律 | 长按屏幕 | 长按 `空格` | 在旋律长音处取值 |
| *(隐藏)* **不操作** | 保持当前层 | — | — | **双闸门夹击时，"不操作"才是正解** |

> **设计要点（P3 的体现）**：引入"**不操作也是有效输入**"（双闸门 twin），打破"见障碍就按"的条件反射，迫使玩家**判断**而非**反应**（`超频长阶.md:115-117`）。

**可玩性校验**：层切换仅 90 ms，而最短障碍间隔为 1 拍（380 ms @158 BPM）⇒ 操作层不成为瓶颈；即使在十六分密段（95 ms），玩家也能从容完成切换（`超频长阶.md:131-133`）。

### 3.3 误导体：用机制筛选玩家行为

```
音乐事件轴:   ●───────●───────●───────●      （onset 真实落点）
视觉障碍轴:   ◆──◆────◆───◆──────◆──◆       （含错位假障碍）
                   ↑ 与 onset 不对齐 = 必须无视
```

- `decoy` 被放在**非 onset** 位置，其"看起来该躲的时刻"与音乐无关；
- 撞上 `decoy` **不扣分、不断连击**，只有视觉火花；
- 真正的惩罚是**间接的**：若为躲 `decoy` 而错过紧邻的真实闸门，就会 **Miss**；
- **设计意图**：让"凭视觉反应"的玩家吃亏，让"跟着音乐呼吸"的玩家受益（`超频长阶.md:150-161`）。

### M1 ★ 副歌开闸（Chorus Gate）

- **玩法**：进入副歌的**那一拍**，跑道"开闸"——镜头拉近到第一人称、速度冲到 15 u/s、误导体成批登场；玩家在副歌内进入"过载态"，连击倍率封顶更快。
- **音乐结构映射**：主歌铺垫 → 副歌爆点。以 `sections[kind==='chorus', energy=1.0]` 的交界时刻作为"开闸拍"。
- **代码钩子**（本项目已具备或已有现成接线位）：
  - 段落能量已驱动冲刺：`Track.speed()`（`声浪星球.html:3185-3189`，`energy≥0.85 → SPRINT`）；
  - 段落镜头提示已存在：`Chart.lensCues` 里 `bar24 → onboard`（`tools/gen_causeway.js:355`），由 `Lens.toLens` 消费（`声浪星球.html:4437-4444`）；
  - 误导体在副歌段生成（`gen_causeway.js:317-320`），运行时由 `Judge.cross` 判"只留痕不扣分"（`声浪星球.html:3488-3491`）；
  - **新增接线位**：死事件 `cw:layer`（`声浪星球.html:3177`）——可在开闸瞬间广播一次"过载态"事件驱动全屏脉冲。
- **感知**：听＝BGM 进入满编（kick 4/4）；视＝FOV → 92 + 副歌标签；操＝节奏应答变密。

### M2 ★ Drop 俯冲（Drop Slam）

- **玩法**：高潮段（Drop）进入时，赛道短暂"塌缩"为一次**强制大动作**——Drop 第一拍要求玩家完成一次"同调长按"或双闸门穿缝，做对给全段最高单次分。
- **音乐结构映射**：Drop = 编曲全要素同时切入的**时间点**（流行/电子特有结构；项目原设"Drop 飞行段"，`声浪星球-游戏总开发文档.md:159`）。
- **代码钩子**：
  - 高潮段定义在 `gen_causeway.js:138-139`（`climax`，`energy 1.0`，主导机制 `twin`）；
  - 双闸门"不操作才是正解"已有判定：`Judge.cross` 的 `answer==='hold'` 分支（`声浪星球.html:3492-3495`），静默窗口 `Obstacle.JUDGE_HOLD=0.25`（`声浪星球.html:3811`）；
  - 同调长音触发点：`chart.sustains` → `CWReso`（`声浪星球.html:3642-3644`）；
  - **新增**：把"Drop 拍"写进 `sections[].special`（**schema 已预留该字段**，`gen_causeway.js:403` 已输出），运行时读取即可，判定层零改动。
- **感知**：听＝Drop 低频轰入；视＝镜头俯冲 / 速度峰值；操＝一次"必须做对"的全押。

### M3 ★ 预副歌蓄能（Build Charge）

- **玩法**：预副歌（铺垫段）持续按住"同调"蓄能，能量条随旋律上行爬升；蓄满则在副歌开闸时获得额外加成，漏按则只吃基础倍率。
- **音乐结构映射**：Pre-Chorus 的功能是**张力爬升**——用"音乐正在积累"这件事本身做倒计时压力源。
- **代码钩子**：
  - **现成未消费数据**：`melody.slope`（`gen_causeway.js:411` 已随谱面输出，**运行时零消费**）——用其正值段作为"蓄能窗口"；
  - 长按入口 `CWInput.resonating` 已有 `begin/end` 与 `Bus.emit('cw:resonate')`（`声浪星球.html:3434-3471`、`:3462/3468`）；
  - 倍率汇入口 `CWScore.mult/amo`（`声浪星球.html:3522-3523`）已并入结算式（`:3538`）——新加一个乘区即可复用整条计分链。
- **感知**：听＝旋律上行、配器逐层加入；视＝能量条爬升 / FOV 缓拉伸；操＝按住蓄能。

### M4 ★ 终曲终结拍（Final Cadence）

- **玩法**：歌曲最后一段进"渐慢收束"，速度回落、障碍变疏；**最后一个音**要求一次决定性同调长按，命中给"终章加成"并直接决定结算评级上限。
- **音乐结构映射**：Outro 的收束感与终止式（cadence）——流行乐结尾特有。
- **代码钩子**：
  - 曲终判定已存在：`CWResult.tick`（`声浪星球.html:3769-3773`，`songT ≥ duration−0.05` 弹结算）；
  - 结算面板 schema 已含 `resoPerfect/resoTotal/onBeat`（`声浪星球.html:3752-3753`）；
  - **已落地**：causeway 关卡保持 5 段（以 climax 收尾）；song2 与运行时分析器已含 `outro`，`CWResult` / `Track.speed` 自动消费，判定层零改动。
- **感知**：听＝渐慢、尾音留白；视＝赛道收束、镜头拉回追尾；操＝最后一次"定生死"的长按。

### M5 ◆ 旋律航线（Melody Lane）

- **玩法**：赛道上方悬浮一条随**旋律走向**起伏的"航线"；当玩家所处层位与航线趋势一致，命中获得"和声加成"；旋律下行长句时航线沉入低位、上行时抬升。
- **音乐结构映射**：用流行乐主旋律的**音高轮廓**（上行 / 下行 / 持续）直接决定玩法，而非仅用鼓点。
- **代码钩子**：
  - **现成未消费数据（双份）**：`melody.slope`（`gen_causeway.js:411`，±0.3 为可辨阈值）与 `mood.energy`（`gen_causeway.js:412`，20 Hz 情绪能量）；
  - 相机/FOV 已由 `Lens` 按 `cue:'melody'/'mood'` 驱动（`gen_causeway.js:353-361` → `LensArbiter`，`声浪星球.html:4501-4515`）——可复用同一数据源驱动"航线"几何；
  - 层判定可读 `Track.effLayer`（`声浪星球.html:3168` / `:3504`）与 `layerY`（`:3217`）。
- **感知**：听＝旋律线；视＝航线起伏（新视觉走 `dseq(seed)`，见 P6）；操＝"跟着旋律走 = 加分"。

### M6 ▲ 用跑道弹琴（Play the Track）

- **玩法**：每次升 / 降 / 命中都**发出一个音**，且音高对齐当前段落的和声（A 小调音阶）；连击构成一条上行音阶——玩家跑完一段，等于把这段旋律"弹"了一遍。
- **音乐结构映射**：brief 第③路"把操作反解为音乐"（`brief:54-57`）；本项目原表述"**你演奏了一首歌**"（`声浪星球-游戏总开发文档.md:190-201`）。
- **代码钩子**：
  - **雏形已在**：`m1Sfx(kind, step)` 已按半音升格（`声浪星球.html:3300-3339`，`mul = 2^(step/12)` `:3302`，`cwHit` `:3329`、`cwGood` `:3330`）；
  - 命中音随连击升格：`Feedback.sfx(grade, CWScore.combo)`（`声浪星球.html:3514`）；
  - 和声 / 音阶真值：生成器的 `CHORDS`（Am–F–C–G，`gen_causeway.js:161-166`）与 `SCALE`（A 自然小调，`gen_causeway.js:170`）；
  - **新增**：把 `mul` 的取音从"随连击"改为"随段落内音阶步进"——**只改 SFX 参数来源，不动判定 / 计分**。
- **感知**：听＝操作直接产出乐音；视＝命中特效随音高变亮；操＝切层 = 弹音，越准越"成曲"。

### M7 ★ 结构轮转表（Structure Rotation）—— 元机制

- **玩法**：所有段落类型绑定一套"机制词汇表"（教学 / 预判 / 连环柱 / 误导体 / 同调 / 双闸门 / 蓄能 / Drop 全押），换歌时由分析出的段落序列决定玩法组合——**换歌 = 换关**。
- **音乐结构映射**：直接回答机制层的判据（`brief:11`），把"音乐结构 → 机制"做成可复用字典。
- **代码钩子**：
  - 生成器已按 `sec.kind` 分派障碍类型（`gen_causeway.js:302-332`：`intro/verse/chorus/bridge/climax → gate/orb/decoy/twin…`）；
  - 运行时所有消费端都只读 `Chart.data`（`Obstacle` / `Judge` `:3482` / `CWScore` `:3519` / `CWAnt` `:3575` / `CWReso` `:3634` / `Lens` `:4423`），**结构无关、零改动**；
  - **新增**：把 `gen_causeway.js` 中"段落 → 障碍 / 镜头 / 预判"的规则提炼为运行时可调用的 `ChartGen`（文档已将其规划为 `M3-B`：`声浪星球-跑酷音游-开发文档.md:225`）。
- **感知**：听＝每首歌听感不同；视＝赛道节奏与机关构成不同；操＝决策密度随段落起伏。

### 4.1 ★ 关键卖点：已生产、待点燃的"数据弹药"

运行时**实际只消费** `sections / anticipations / sustains / duration / obstacles / lensCues`（已核实：`声浪星球.html:3147/3154/3587/3643/3772/3924/4490/4504`）。而谱面里**已经生成、却还没有人消费**的数据有：

| `phrase.bars` | 17 个 4 小节线 | 镜头/机制切换边界 | 同上 |

## §5 音乐结构 → 机制 映射总表

> **先厘清一件事：这张表是"完整设计词汇（全集）"，不是某一首谱面的实况。**
> 段落种类共 **7 种**，构成机制词汇表的上限；**具体一首歌命中哪几种**，由该歌自身的结构决定：

| 段落 | 参考能量 | 主导镜头 | 主导机制 | 障碍类型 | 玩家被问的问题 |
|---|---|---|---|---|---|
| **前奏 Intro** | 0.30 | 追尾 | 升降教学（安全） | `gate-lo` / `gate-hi` | "这游戏怎么按？" |
| **主歌 Verse** | 0.55 | 追尾 → 俯视 | 首次预判窗口 + M6 演奏 | `+ orb` | "下一段会往哪走？" |

## §6 真实流行乐接入链路

### 6.1 端到端最短链路

> **核心论断**：运行时"判定—计分—镜头—障碍—结算"消费端**零改动**——因为它们全部只读同一份 `Chart.data` schema（已核实：`Obstacle` / `Judge` `:3482` / `CWScore` `:3519` / `CWAnt` `:3575` / `CWReso` `:3634` / `Lens` `:4423` 均无对"歌源"的特判）。

```
选歌 / 上传本地音频
   → [ decodeAudioData  ✅ 已有 ]
   → AudioAnalyzer      ✅ 已建成（P5）
   → ChartBuilder       ✅ 已建成（P5，= 生成期 ChartGen 的运行时版）
   → Chart.set / BGM.useBuffer  ✅ 已建成（P5）
   → 进入 causeway      ✅ 已有（全链路 P0–P5）
```

| # | 步骤 | 状态 | 已有可复用 | P5 实际实现 | 消费端改动 |
|---|---|---|---|---|---|
| 1 | 用户选歌 / 上传音频 | ✅ 已通 | `LEVELS.causeway` + SongSelect 浮层 | `SongSelect.upload(file)` + 隐藏 `<input type=file>`（本地读取，不上传服务器） | — |
| 2 | 取音频字节 | ✅ 已通 | `decodeAudioData` + `createBufferSource` + `loadBGM` | `BGM.useBuffer(buf,key)`：参数化路径，兼容预烘焙歌与运行时 Buffer | **零** |
| 3 | 音频分析 | ✅ 已建成 | 目标 schema 已冻结（＝ chart JSON） | `AudioAnalyzer.analyze(ArrayBuffer)`：自实现 FFT + 重采样，无 `AnalyserNode`/`OfflineAudioContext` 依赖漂移 | **零** |
| 4 | 生成谱面 | ✅ 已建成 | 生成期规则已在 `tools/gen_causeway.js` | `ChartBuilder.build(feat,meta)`：段落语法 → 障碍 / 预判 / 镜头 / slope/mood | **零** |

> **实测校准（P5 门禁 `tools/analyze.js`）**：song2 → 分析 BPM 112.3（真值 112）、44 小节、6 段含 preChorus+outro、障碍自洽；causeway → 分析 BPM 161.5（真值 158）。两次分析结果**逐字节一致**（确定性），且分析全程**零写入**（R2 随机流 `dseq`/`lcg` 不受影响）。

**一句话答辩**：*"我们的引擎已经是 schema 驱动的——真实歌只要产出同一份 JSON，判定、计分、镜头、结算一行都不用改。"*

### 6.2 理想形态 / 现实路径（双栏）

| | **理想形态**（本设计追求） | **现实路径**（可立即交付） |
|---|---|---|
| 音乐来源 | 真实流行乐（可交互授权） | ① 程序化合成的《超频长阶》+ song2（预烘焙）；② **任意一首本地歌**（P5 运行时分析） |
| 谱面 | 自动 `AudioAnalyzer` 产出段落/旋律/情绪 | ✅ **两条路都已通**：预烘焙走"**真值谱面**"（WAV 与谱面同源、逐位对齐、运行时零分析）；任意歌走运行时 `AudioAnalyzer` |
| 版权 | 版权方开放"共创授权"（颗粒度细到可交互素材层） | 严守 R6 红线：仅**本地分析**、不上传、不内置受版权曲目 |

> **必须诚实标注**：真实歌接入的**技术缺口（分析器）已在 P5 补齐**；但**最大门槛不是技术，是"权利范围"**——`brief:44` 的尖锐结论"技术可行区与版权可行区几乎不重叠"仍然是那堵墙。本设计把它写进产品主张的一部分，而非回避。

## §7 工程与红线

### 7.1 已有的工程护城河

1. **同源真值谱面**：生成期 WAV 与谱面在同一次采样循环里产出，onset 与采样**逐位对齐**，运行时**零分析**（`tools/gen_causeway.js:1-11`）。
2. **起播锚定**：`bgmT0 = currentTime − tAtDist(dist)`（`声浪星球.html:3391-3394`）解决音频手势延迟对位——多数 Demo 在这一点上翻车。
3. **schema 驱动**：判定 / 计分 / 镜头 / 障碍全部只读 `Chart.data`，对"歌源"零特判。
4. **可量化的门禁体系**：`causeway` 专用 14 项断言（`tools/causeway.js`）+ 四场景 `heroC` **逐位一致**门禁（`tools/quadcheck.js`）+ 性能 calls 红线。**工程质量本身即是护城河。**

### 7.2 新增机制必须遵守的纪律

- **逻辑只在 `if(!FREEZE)` 内执行**，函数体内再自守 `if(FREEZE) return`（双保险）；`?freeze=1` 下定帧不得写相机 / 改 `scene.children` 数量。
- **视觉零漂移红线 R1**：四场景 `heroC` 逐位一致受 `quadcheck` 保护；**任何自动生成物只进 `causeway` 新场景**（有独立基线），不触碰四场景几何。
- **随机流纪律 R2**：新增视觉标记一律走 `dseq(seed)`，**绝不消耗全局 `rnd()`**。
- **共享模块零改动**：`PlayerController` / `CameraRig` / `Lane` 源码不动，新行为走**调用点**或经 `LEVELS` 模式分支注入。
- **提交必跑门禁**：`quadcheck → budget → playtest → showcase → causeway`。

（纪律出处：`声浪星球-跑酷音游-开发文档.md:103-110`、`:303`；`超频长阶.md:404-409`。）

## §8 夺冠论证

### 8.1 为什么这套设计能赢（五角度）

1. **差异化**：主流音游停在"类型层"（换歌不换规则），我们把音乐推到"机制层"——**音乐时间结构直接决定操作**。记忆点就是那句判据式表达：**「换歌即换关」**。
2. **可演示性**：
   - **15 秒看懂**：误导体——"看着像障碍、其实无害；只有跟着音乐的人不吃亏"，一眼即懂、可现场演示；
   - **30 秒上手**：单输入维度（升 / 降 / 长按），学习成本极低；
   - **镜头会说话**：5 镜头由音乐驱动（`Lens` `:4423`），"音乐一变、画面随动"极具观赏性；
   - **已是可跑全链路**（曲终自动结算 `CWResult` `:3769`），**不是 PPT**。
3. **与赛事方向 A 对齐**：方向 A = "上传任意歌曲 → 自动生成关卡"。本方案是方向 A 的"**最贵的下半场**"——方向 A 通常止于"生成下落式音符"，而"生成之后拿什么玩"这一环，我们**现成**。Demo 可演示"一首歌 → 一条跑道"，字面命中赛题。
4. **答辩叙事**：痛点（玩家愿为音乐聚起来，但音乐往往只是"被放进游戏"，而非"成为游戏"）→ 冲突（两道锁）→ 应答（**把音乐结构翻译成跑道**）→ 金句（"我们做的不是第 N 个音游，是把流行乐从'听'的位置，挪到'决定怎么玩'的位置"）。
5. **技术护城河**：同源真值谱面逐位对齐 + 起播锚定 + schema 驱动 + 门禁体系——**用数字说话**（14 项断言 / `heroC` 逐位一致 / 448 onsets 逐位对齐采样）。

### 8.2 最可能的评委质疑 & 应答

| 质疑 | 应答 |
|---|---|
| **"这不就是把 Beat Saber / 世界计划换个皮？"** | 类型层 vs 机制层之别：他们"换歌不换规则"，我们由音乐段落决定机制组合（M7）。可**现场用同一引擎跑两首结构不同的歌 → 玩法不同**来证明。 |
| **"版权怎么办？（方向 A 的致命伤）"** | 三层回应：① 已有红线 R6 本地分析、不上传、不内置受版权曲（`声浪星球-跑酷音游-开发文档.md:110`）；② 理想形态需"共创授权"，我们把叙事定位为"**授权范式的接口提案**"（`brief:65`）；③ Demo 用自制/授权素材，**技术链路与素材权利解耦**。 |
| **"单赛道太单调，玩两遍就腻。"** | 变化来自**歌**而非赛道：`ChartGen` 按段落序列轮转机制（M7）；再加难度档位（轻松/标准/极限）。 |
| **"自动生成会破坏你引以为傲的视觉复刻。"** | 自动生成**严格限定在 `causeway` 新场景**（有独立基线），不触碰四场景几何；新视觉走 `dseq` 独立随机流 ⇒ R1 门禁不受影响。 |
| **"分析和判定不准，歌一复杂就崩。"** | 主演示限定节拍规整的曲风；提供"手动校准 / 贴拍偏移"兜底；判定口径按 BPM 归一（P4）。 |
| **"不就是自嗨？"** | 用可演示的"误导体"直接证明用户价值：**凭视觉反应的人吃亏，跟着音乐的人受益**——一首歌就能让评委亲身体验差异。 |

## §9 风险与对策

| # | 风险 / 张力 | 为何是真风险 | 对策 |
|---|---|---|---|
| **R-1** | **版权"权利范围"** | 流行乐权利是碎的（母带权 + 词曲同步权）且多为限时授权；买得到"播放"，买不到"可改造/可交互"（`brief:35-42`）。技术可行区与版权可行区几乎不重叠（`brief:44`）。 | 理想形态 + 现实路径双栏；Demo 用自制素材；本地分析不上传（R6）；把"共创授权颗粒度"写成产品主张的一部分，而非回避。 |
| **R-2** | **注意力被再次横向抢走** | 单赛道的全部价值成立于"决策维度=时间"；M5 / M6 若不慎引入"侧向选择"，会立刻退回类型层。 | 红线：任何新机制**不得引入新的空间维度**（P1）；M5 / M6 只做**纵向 / 听觉**映射。 |
| **R-3** | **单赛道重复可玩性** | 无分岔 ⇒ 熟悉谱面后边际体验下降。 | 靠"换歌即换关"（M7）+ 难度档位 + 段落机制轮转提供变化；内容量来自**歌库**，不来自赛道数。 |
| **R-4** | **视觉零漂移红线 vs 自动生成关卡** | R1 要求定帧 `heroC` 逐位一致；自动生成的音符 / 航线是**改变布局**的新物体。 | 生成物**只进 `causeway` 新场景**（独立基线）；视觉走 `dseq(seed)` 不扰动全局 `rnd()`；四场景几何零改动。 |
| **R-5** | **判定口径跨歌一致性** | 现用**绝对毫秒** `P=0.080 / G=0.160`（为对齐四场景手感），同一毫秒窗口在高 BPM 歌里相对更松、低 BPM 更紧 ⇒ 体感难度漂移。 | 引入"**按 BPM 的窗口归一**"（或拍相对窗口 + 上下限夹取），并在文档里讲清"为何放弃纯拍口径"。 |
| **R-6** | **结构检测对自由节奏不可靠** | Verse / Chorus / Drop 边界检测在古典 / 自由节奏上会误判。 | 主演示限定流行 / 电子；提供"手动标注段落"高级入口兜底。 |
