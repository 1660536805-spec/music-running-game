## 2. 核心概念与世界观

### 2.1 一句话定位

> **每一首歌，都是一颗等你降落的星球。**

用户上传/选择一首歌，系统把这首歌"翻译"成一颗独一无二的 3D 星球：能量决定山有多高、音色决定星球是什么颜色、节奏决定机关有多密、调式决定天空是什么天气。然后，你降落到这颗星球上，跟着自己的歌跑酷。

### 2.2 概念递进（为什么是"星球"而不是"关卡"）

| 阶段 | 表述 | 问题 |
|---|---|---|
| v0 | "把你的歌变成音游关卡" | 偏工具、偏功能，缺少情感 |
| v1 | "歌单 = 游戏库" | 用户价值清晰，但仍停留在"关卡"心智 |
| **v2（当前）** | **"每一首歌，都是一颗星球"** | 把"关卡"升级为"世界"——有地形、有色彩、有天气、有昼夜，天然具备**收藏感**与**探索感**，为后续"星图 / 行星收藏 / 二次分享"留出叙事空间 |

### 2.3 独创性公式

> **公共游戏形式 × 私人音乐数据 = 独创性**

- 跑酷（公共形式）人人都会做；但把"**用户自己的歌**"作为关卡数据源（私人数据），组合出的是"只属于我的关卡"。
- 关键区别在于**映射方向**：

| 映射方向 | 代表产品 | 结果 |
|---|---|---|
| 音频 → **视觉** | 频谱可视化、音乐可视化壁纸 | 好看，但"不能玩" |
| 音频 → **新歌** | AI 作曲 / 唱歌 | 撞车 TME 自家产品「未音 Vemus」，质量不可控 |
| **音频 → 玩法（本项目）** | 声浪星球 | **没人这么干过**——声音直接决定"怎么玩" |

### 2.4 定位象限

```
                 高交互（要"操作"）
                        ▲
        音游 / 本项目 ●  │
        （音频→玩法）    │   ● 传统音游（固定曲库）
                        │
  ── 私人数据 ────────────┼──────────── 公共数据 ──
                        │
        ● 音乐可视化      │   ● 电台 / 歌单推荐
        （音频→视觉）     │
                        ▼
                 低交互（只"看/听"）
```

声浪星球占据**"高交互 × 私人数据"**象限——这正是当前的红利空位。

### 2.5 落地方向（对外故事）

- 短期：独立 Web 游戏（浏览器即玩，扫码即用，天然适合路演 Demo）。
- 中期：作为 QQ音乐 / 全民K歌 的「唱完即可玩」增值玩法——**唱完一首歌，立刻得到一颗属于你的星球**。
- 版权：Demo 使用无版权 / 自制素材，规避版权争议。

## 3. 核心玩法设计

### 3.1 操作方案（移动端优先）

| 操作 | 移动端 | 桌面端 | 说明 |
|---|---|---|---|
| 跳跃 | 屏幕**点按** | `空格` / `↑` | 越过鼓点机关、吃空中音符 |
| 滑行 | 屏幕**下滑** | `↓` | 穿过低矮障碍 / 加速带 |

> 设计原则：**两个操作、无需教程**。所有认知成本都花在"看懂星球"上，而不是"学操作"。

### 3.2 核心游戏循环

```
选歌 ──► 生成星球 ──► 降落跑酷 ──► 结算评级 ──► 生成"你玩出来的歌"
 ▲           (3秒魔法)      (2键 + 段落演出)      (S/A/B/C)      (二次传播)
 └────────────────────────── 再来一颗 ◄──────────────────────────┘
```

### 3.3 机关类型（音频 → 地形的直接映射）

| 音乐元素 | 游戏机关 | 视觉形态 |
|---|---|---|
| 底鼓 kick（强拍） | **跳跃台** | 地面隆起的小台，需要起跳 |
| 军鼓 snare | **加速带** | 地面质变条带，踩上提速 |
| 长音 / 铺底 pad | **滑轨 grind** | 悬浮长条，可滑行穿越 |
| 高音 melody | **悬浮音符** | 空中的水晶 orb，跳起来吃，加分 |
| 段落转折 | **装饰地标** | 陨石坑、水晶柱、信号塔、环形门等 |

### 3.4 歌曲段落驱动的节奏曲线

| 段落 | 进度区间（原型） | 玩法强度 | 镜头 |
|---|---|---|---|
| 主歌 Verse | 0–36% | 常规跑动，稀疏机关 | 贴地跟随 |
| 预副歌 Pre-Chorus | 过渡 | 机关渐密，引导起跳 | 贴地跟随 |
| 副歌 Chorus | 36–66% | 连跳 + 滑轨，机关最密 | 拉高俯瞰 |
| Drop | 66–90% | **飞行段**，高速冲刺 | 环绕飞行 |
| 桥段 Bridge | 过渡 | 喘息，机关骤减 | 平稳 |
| 尾声 Outro | 90–100% | 减速收尾 | 绕星球环拍 |

> 这是"歌曲结构驱动玩法"的落地：**玩家不是在打一首歌，而是在跟着歌的情绪跑一场**。

### 3.5 判定与计分

| 判定 | 条件 | 反馈 |
|---|---|---|
| **Perfect** | 精准踩中机关 | 得分 × 高倍率、连击 +1、白屏微闪 |
| **Good** | 命中但时机偏差 | 得分 × 低倍率、连击 +1 |
| **Miss** | 未命中 | 连击归零 |

**计分公式（原型）**：

```
跳跃台命中： score += round(120 × (1 + combo × 0.03))
悬浮音符命中：score += round(80  × (1 + combo × 0.03))
连击能量条：  energy = min(100%, combo × 4%)
```

**评级阈值（原型）**：

| 评级 | 最高连击 |
|---|---|
| S | ≥ 40 |
| A | ≥ 24 |
| B | ≥ 12 |
| C | < 12 |

### 3.6 结算与"你玩出来的歌"

结算页是一张**战绩卡**（评级 + 最高连击 + 完美率 + 得分 + 星球缩略图），可分享。

**爆点机制——"你玩出来的歌"**：把玩家本次的操作序列（每次跳跃的时机与强度）反解成一段节奏/旋律，与原始歌曲叠加播放。也就是：

> **同一套引擎的双向映射**：歌曲 →（分析）→ 关卡去玩；操作 →（合成）→ 音乐输出。
>
> "你不仅玩了一首歌，你还**演奏**了一首歌。"

这是分享传播的核心钩子——每个人跑出来的"歌"都不一样。

## 4. 音频解析与关卡生成系统（技术核心）

> 这是整个项目的护城河。目标：**在浏览器里、离线、几秒内**，把一首任意音频解析成一套可直接驱动 3D 世界的结构化数据。

### 4.1 输入

- 本地上传的音频文件（`<input type=file>` / 拖拽）
- 未来可接 TME 曲库（演示阶段用无版权素材）

### 4.2 分析管线（Web Audio `OfflineAudioContext`）

| 步骤 | 方法 | 输出 |
|---|---|---|
| ① 解码 | `decodeAudioData` | PCM 波形 |
| ② BPM 检测 | 能量包络自相关 / 节拍跟踪 | 全局 BPM |
| ③ 节拍 & onset 检测 | 能量峰值 + 谐波变化（spectral flux） | 每个鼓点/音符的时间戳与强度 |
| ④ 频谱音色 | 分帧 FFT → 频谱质心 / 高频占比 | "明暗"标量（→ 星球主色） |
| ⑤ 能量曲线 | 分帧 RMS | 逐段能量包络（→ 地形高度） |
| ⑥ 节奏密度 | onset 在滑动窗口内的计数 | 逐段密度（→ 机关密度） |
| ⑦ 段落分割 | 自相似矩阵 / 能量突变点 | Verse / Chorus / Drop … 边界 |
| ⑧ 调式情绪 | 音高类分布 / 大小调推测 | 情绪标签（→ 天空/天气） |

### 4.3 数据产物：BeatMap JSON（示意）

```json
{
  "meta": { "title": "孤勇者", "bpm": 128, "duration": 245.0 },
  "palette": { "primary": "#5FD3C0", "sky": "#CFEBFB", "weather": "clear" },
  "sections": [
    { "type": "verse",   "start": 0.0,  "end": 42.0 },
    { "type": "chorus",  "start": 42.0, "end": 78.0 },
    { "type": "drop",    "start": 78.0, "end": 112.0 }
  ],
  "events": [
    { "t": 12.480, "type": "pad",  "strength": 0.82 },
    { "t": 12.960, "type": "orb",  "strength": 0.55 },
    { "t": 13.440, "type": "rail", "strength": 0.30 }
  ],
  "terrain": { "amp": [0.4, 0.9, 0.6, 1.2], "seed": 20261006 }
}
```

### 4.4 音频特征 → 星球/关卡特征（**这是"设计 + 技术"合一的独创点**）

| 音频特征 | → 星球/关卡特征 | 效果 |
|---|---|---|
| **能量** | 地形起伏 | 副歌高能量 → 高耸三角山脊；主歌低能量 → 辽阔平原 |
| **音色明暗** | 星球主色 | 明亮电子音 → 薄荷蓝绿；低沉厚音 → 芥末橙紫 |
| **节奏密度** | 机关密度 | 鼓点越密，跳跃台/滑轨排布越密 |
| **调式情绪** | 天空与天气 | 大调 → 晴朗暖光；小调 → 暮色紫空；Drop → 流星雨 |

### 4.5 兜底与降级策略（保 Demo 稳定）

1. **手动校准**：BPM 检测不准时，提供 ±微调滑杆。
2. **曲风限定**：Demo 阶段主打流行 / 电子（节拍规整），对古典/自由节奏标注"实验性"。
3. **预置谱面兜底**：分析失败时回退到内置的 2~3 首预置 BeatMap，保证永远有东西可玩。

### 5.3 材质规范

```js
new THREE.MeshPhongMaterial({
  color,            // 或 vertexColors: true
  flatShading: true, // 低多边形关键：保留硬边
  shininess: 0       // 无高光，纯玩具感
})
```

- 地形：`vertexColors` + 逐顶点 `shade()` 明暗扰动，用三角面拼出"糖果色块"。
- 天空：`BackSide` 渐变穹顶（天顶天蓝 → 地平线暖白），加若干 `IcosahedronGeometry` 天体（大行星 + 环 + 卫星 + 太阳球）。
- 雾色 = 地平线色，让远景地形无缝融进天空，消除"雾墙"。

### 5.5 动效规范

- **BPM 同步**：节拍触发时相机轻微震动（`beatFlash * 0.28`）+ 白屏微闪。
- 主角：奔跑四肢摆动（`elapsed * 11.5` 相位），跳跃时手臂上举、身体前倾。
- 天体：缓慢自转（大行星 0.03 rad/s）。
- UI：能量条 / 进度条 / 评级随连击实时变化。

## 6. 镜头与演出系统

> 用户明确要求：**做成 3D，且视角要变化**。镜头本身就是演出的一部分。

### 6.1 五段镜头分镜（状态机）

| 段落 | 触发进度 | 机位 | 相机行为 |
|---|---|---|---|
| ① 俯冲降落 | 0–7% | 高空俯冲 | 从高空 46 高度俯冲贴近地面（开场仪式感）|
| ② 贴地跟随 | 7–36% | 第三人称跟随 | 机位在角色**后上方**，贴地跟随（默认视角）|
| ③ 拉高俯瞰 | 36–66% | 拉高俯瞰 | 抬升至 +14 高度，纳入更多地形（副歌）|
| ④ 环绕飞行 | 66–90% | 环绕 | 绕角色做圆周环绕运动（Drop 的高潮）|
| ⑤ 绕星球环拍 | 90–100% | 大环绕 | 半径 27 的大环绕，抬高视线把天空星球纳入画面（尾声）|

### 6.2 技术实现

- `PerspectiveCamera(58°, aspect, 0.1, 3000)`
- 相机位置 `camPos` / 视线目标 `camLook` 分别用指数平滑插值逼近目标：`lerp(target, 1-exp(-k·dt))`
- 段落切换时在屏幕中央显示段落标签（如"副歌 · 拉高俯瞰"），1.7 秒后淡出

已从 Astroneer 官方商店页抓取 10 张官方截图存于 `astroneer-ref/`，并产出对照预览页 `异星探险家-参考图.html`（逐张标注相机视角类型：第三人称跟随 / 俯瞰全景 / 近景特写 / 洞穴低机位 / 广角仰视 / 强逆光）。

## 7. UI / UX 设计

> 用户明确强调：**游戏 UI 设计是最吸引用户的关键点**。

### 7.1 五个核心界面

| # | 界面 | 关键信息 | 设计要点 |
|---|---|---|---|
| 1 | **选歌页** | "你的歌单就是你的游戏库" | 歌单 = 星图；每首歌以一颗小星球呈现 |
| 2 | **生成星球** | 波形分析 3 秒魔法 | 进度环 + 实时特征 chips（BPM 128 / 能量 高 / 主色 薄荷 / 机关 96） |
| 3 | **游戏中 HUD** | 连击 / 进度 / 得分 + 能量条 | 两点操作提示；段落标签居中浮现 |
| 4 | **结算** | S 评级 + 战绩卡 + "生成你玩出来的歌"按钮 | 评级大字 + 三格数据 + 星球缩略 |
| 5 | **"你玩出来的歌"** | 波形播放页 | 播放按钮 + 波形柱 + 分享 |

### 7.2 设计语言

- **"声波"作为唯一图形语言**：按钮、进度条、评级、卡片都由波形变形而来（第一版方向）。
- **第二版转向异星风格**：以"星球/地形"图形语言为主，承载 Astroneer 概念递进。
- 卡片化、圆角、浅色玻璃拟态（`backdrop-filter: blur(8px)`），底色深空霓虹 → 异星糖果色过渡。
- 移动端优先；HUD 用半透明白卡承载数据，不与 3D 画面争夺注意力。

### 7.3 设计稿文件

- `声浪跑酷-UI设计.html`：第一版（声波语言 + 深空霓虹）
- `声浪星球-UI设计-异星风格.html`：第二版（异星风格，含"音频→星球"映射图解）

## 8. 技术架构

### 8.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 渲染 | three.js（本地 `three.min.js`） | 3D 低多边形友好、体积可控 |
| 模型加载 | `GLTFLoader.js` | 加载 `.glb` CC0 资产 |
| 音频 | Web Audio API（`OfflineAudioContext`） | 离线分析，无需上传服务器，隐私友好 |
| 逻辑/UI | 原生 JS + CSS | 零构建、零依赖、单文件可部署 |
| 部署 | 纯静态页（任意静态托管 / 对象存储 / GitHub Pages / Vercel） | 初赛与决赛都好交付 |

### 8.2 建议模块划分（从原型单文件走向可维护结构）

```
声浪星球/
├── index.html                # 入口（选歌 → 生成 → 游戏 → 结算）
├── lib/
│   ├── three.min.js          # three.js
│   └── GLTFLoader.js
├── src/
│   ├── audio/analyze.js      # ① 音频分析管线（BPM/onset/能量/段落）
│   ├── chart/build.js        # ② 音频特征 → BeatMap（关卡生成）
│   ├── world/terrain.js      # ③ 地形生成（能量驱动顶点位移）
│   ├── world/sky.js          # ④ 天空/天气（调式驱动）
│   ├── game/player.js        # ⑤ 操作 & 判定 & 计分
│   ├── game/camera.js        # ⑥ 镜头状态机（5 段）
│   ├── audio/synth.js        # ⑦ "你玩出来的歌"合成
│   └── ui/*                  # ⑧ 选歌/生成/HUD/结算/song
├── assets/                   # 44 个 CC0 .glb 模型
└── docs/                     # 本开发文档
```

### 8.3 数据流

```
音频文件
  └─(OfflineAudioContext 分析)─► 特征对象 {bpm, energy[], onsets[], sections[], timbre}
        ├─(地形映射)─► 地形高度场 ─► three.js BufferGeometry
        ├─(配色映射)─► 调色板 ─► 材质/天空/天气
        ├─(关卡映射)─► 机关序列 ─► 跳跃台/滑轨/orb 实例
        └─(段落映射)─► 镜头时间轴 ─► 相机状态机
玩家操作
  └─(判定/计分)─► 连击/能量/评级
        └─(反解合成)─► "你玩出来的歌" 波形
```

### 8.4 性能预算（目标：中端手机 60fps / 低端 30fps）

| 项 | 预算 |
|---|---|
| 三角面（地形 + 装饰） | < 150k |
| 同屏实体 | < 120（装饰循环复用） |
| 纹理 | 0（无贴图） |
| draw call | < 200 |
| 首屏资产 | 44 个 glb 总大小控制在数 MB 内，逐个串行加载并报进度 |

| 节拍检测对古典/自由节奏不准 | 关卡对不上拍，体验崩塌 | 限定流行/电子做 Demo；提供**手动校准**滑杆；分析失败回退**预置谱面** |

| 移动端性能不足 | 路演现场卡顿 | 无贴图 + 三角面预算 + 装饰循环复用；准备降级开关 |
