# 真实歌分析 · 压力测试报告

> **性质**：交付验证文档（P5 运行时音频分析器的鲁棒性实测）。
> **红线声明（R6）**：测试所用**音频样本为免版税 / CC-BY 曲目**（Kevin MacLeod，incompetech.com）⇒ 依许可**可入库 / 可部署并署名**——两首说唱已转正为内置曲（`assets/rap-galactic.mp3` / `assets/rap-christmas.mp3`，署名见 `声浪星球.html` 与 `README.md`）。本报告同时记录**指标数字与结论**。

---

## 1. 测试目的

验证 P5 运行时音频分析器（`AudioAnalyzer` + `ChartBuilder`）面对**真实说唱 / 真实歌**（而非程序化合成曲）时：

1. 能否产出**结构自洽、可玩**的谱面；
2. **BPM 估计误差**是否在可接受范围（目标 < 3%）；
3. 是否保持 **P5 核心承诺——确定性**（同一首歌两次分析逐字节一致）；
4. **分析耗时**是否满足"现场上传即跑"的体验要求；
5. 暴露**已知失真**，如实记录。

---

## 2. 方法与环境

- **运行方式**：本地静态服务（`python3 -m http.server 8777`）→ headless Chromium 载入 `声浪星球.html` → 调门禁钩子 `window.__analyze(url)`（纯探针：分析 → 建谱，不注册、不切场景）；同一进程内**连跑两次**，对比谱面 JSON 的 SHA-256。
- **算法口径**：与 `tools/analyze.js` 一致——自实现 FFT（N=1024 / HOP=512 / Hann）+ 线性重采样至 SR=22050，固定阈值，`Float64Array` 顺序累加，量化出口 `+v.toFixed(n)`。
- **样本来源**：incompetech.com（Kevin MacLeod，**CC-BY** 免版税直链 mp3），说唱风格。

## 6. 结论

1. **确定性成立**：两首真实说唱（mp3、非合成）两次分析**逐字节一致**——P5 核心承诺在真实素材上依然成立。
2. **BPM 估计可用且跨速稳**：120 BPM 与 90 BPM 两档误差分别为 −2.1% / −1.0%；说明"自相关 + 对数正态先验 + 倍频归一"对说唱也稳健。
3. **速度达标**：141 s / 186 s 的歌分别在 **~0.3 s / ~0.4 s** 完成分析，现场"上传即跑"体验良好。
4. **结构自洽**：两曲均产出 9 段、`intro` 首 / `outro` 末强制、`preChorus` 紧邻 `chorus` 前、`climax` 在 `chorus` 后——段落语法在真实说唱上给出合理序列。
5. **零报错**：分析 → 建谱链路无控制台错误。

## 7. 已知失真（如实记录）

> 以下为**实测暴露**的弱点，非隐藏项；部分可作后续改进项。

1. **动态范围压缩 ⇒ 段落能量区分度弱 / 多数段落触发冲刺**
   两首说唱的**中段 energy 高度集中在 0.77–1.00**。由于运行速度按 `Track.energy ≥ 0.85 ⇒ SPRINT` 触发，**Galactic Rap 7/9 段、Christmas Rap 6/9 段**处于冲刺速度，段落间的速度起伏被抹平。
   *成因*：`energy = 段内 RMS ÷ 全曲最大段 RMS`；现代混音动态压缩 + 说唱持续"满编"，会把中段整体推高。
   *影响*：观感偏"平"；**机制层（段落 kind 分派）不受影响**。
   *候选改进*：以**相对中位数的 z-score / 分位映射**替代纯 max 归一，保留段间对比。

2. **段落 kind 允许重复**（两曲均现 `verse ×2`、`bridge ×2`）
   `ChartBuilder` 对 K 个能量块逐一标注，未强制 kind 唯一。**属设计选择而非缺陷**（每块仍独立分派机制），但会让"段落轮转"观感单一。
   *候选改进*：对相邻同 kind 块做能量二次区分（如高/低 verse）。

3. **`sections[].camera` 运行时为死字段**
   `ChartBuilder` 对每段统一写 `camera:'chase'`，但运行时**无任何消费端读取**（镜头变化走 `lensCues` → `LensArbiter`）。**已核实**：全文件无 `sec.camera` / `s.camera` 读取 ⇒ 非功能缺陷，但易被误读为"每段镜头一致"。
   *候选改进*：或删除该字段，或让分析器按 kind 生成差异化的 `lensCues`（现按 4 小节边界生成 8 条）。

4. **BPM 估计存在 ±2% 量级误差**
   对多数曲风可接受；对**自由节奏 / 变速**曲目仍可能误判，属**已知边界**（主演示限定节拍规整曲风；提供手动校准兜底）。

5. **`bars` 恒为 69（两曲巧合）**
   两首样本时长不同（141 s / 186 s）却都得 69 小节，源于 `CHUNK` 模板与 `bars=ceil(duration/bar)` 的组合；属正常，非缺陷——但说明**段数/小节数并非时长线性**，演示时勿以段数推断曲长。
