# 声浪星球 · 跑道切换移动控制方案

> **版本**：v1.1 ｜ **定位**：跑酷音游的**移动端操控范式**设计规格
> **上游文档**：`声浪星球-跑酷音游-开发文档.md` v1.1（本文是其 §4 / §5 的操作层细化）
> **状态**：✅ **M3-OP 已落地**（2026-10-07，`声浪星球.html` @2693+）｜ 输入改用半区轻点，详见 §11
> **一句话**：**移除虚拟摇杆，角色自动向前奔跑，玩家只做一件事——在拍点之间换道。**

---

## 0. 设计总纲

### 0.1 为什么移除虚拟摇杆

| 现状（自由跑酷）问题 | 移除后的收益 |
|---|---|
| 左手压摇杆 + 右手点按，**双手占用、注意力割裂** | 单手/拇指即可完成全部操作，**视线可留在前方跑道与音乐反馈上** |
| 8 自由度连续输入，判定"意图"模糊（跑多快？跑偏多少？） | 1 自由度离散输入，**意图明确可判定** |
| 与音游的节奏感割裂（摇杆是连续量，音游是离散量） | 换道天然是**离散击打**，可直接挂判定 |
| 移动端虚拟摇杆遮挡画面、误触率高 | 屏幕全释放，HUD 与跑道可视化更完整 |

### 0.2 核心设计信条

1. **一次输入 = 一个节奏事件**：换道即"击打"，落在拍点上是 Perfect。
2. **低延迟优先于花样**：任何装饰性手势识别都不如"点了就动"。
3. **不给惩罚性死手**：越界不是"没反应"，而是"撞到软墙"。
4. **难度跟着音乐能量走**，而非平均分配（见 §4）。
5. **必须可达**：谱面生成要做可达性校验，**不允许出现"物理上赶不及"的谱面**。

# 1. 左右切换的输入方式

## 1.1 四条候选通道

| 通道 | 平台 | 识别延迟 | 准确率 | 是否需看屏 | 结论 |
|---|---|---|---|---|---|
| **A · 屏幕左右半区轻点** | 移动 | **20–33ms**（1 帧内） | 高 | ❌ 不需要 | ✅ **主通道** |
| **B · 水平滑动手势** | 移动 | 80–150ms（识别 + 方向判定） | 中（斜向误判） | ❌ 不需要 | ✅ **辅助通道** |
| **C · 左右虚拟按钮** | 移动 | 30–50ms | 最高 | ⚠️ 需瞄 | 🔶 **可选设置项，默认关** |
| **D · 键盘 ← → / A D** | 桌面 / 外接键盘 | ~16ms | 最高 | ❌ 不需要 | ✅ **桌面通道** |
| ~~E · 陀螺仪体感~~ | 移动 | 120ms+ | 低（噪声/漂移） | — | ❌ **不采用** |

## 1.2 通道 A · 屏幕半区轻点（移动端主通道）

**做法**：屏幕**左半区任意位置轻点 → 左移一格**；**右半区 → 右移一格**。

**为什么它是主通道**：
- **零手势识别成本**：不需要等滑动阈值判定，触摸事件到达即可执行 → 延迟最低。
- **盲操友好**：视线不用下移找按钮，专注角色与前方音符。
- **与"跑道"心智模型一致**：屏幕左右 = 跑道左右，映射关系天然。
- **拇指友好**：单手横握时拇指自然覆盖屏幕两侧。

**边界定义**：`x < innerWidth/2` → 左；`x ≥ innerWidth/2` → 右。
建议在左右半区**各叠加一个极淡的指示三角**（`opacity ≤ 0.18`），首次游玩用 3 秒淡出提示后永久隐藏 —— 解决"新玩家不知道能点"的可发现性问题。

## 1.3 通道 B · 水平滑动（辅助通道）

**触发条件**（三者同时满足）：
- `|dx| ≥ 40px`
- `|dx| > |dy| × 1.2`（横向意图占优，避免与上滑跳跃冲突）
- 触摸时长 `< 500ms`（避免拖拽误判）

**用途**：**连续快速换道**时更省力（一次大幅滑动 + 惯性补按），以及"用力甩"的爽感。

**与通道 A 的互斥规则（重要）**：
> 同一次 `touchstart → touchend` 周期内，**最多产生 1 次 switchIntent**。
> 采用 **"先满足者胜"**：若 `touchend` 时轻点条件已达成（总位移 < 40px），判定为 Tap；否则若滑动条件达成，判定为 Swipe。**两者不叠加**。

这样避免"快速滑动时先被判成 Tap 松手换一次、滑完又换一次"的**双触发 bug**。

## 1.4 通道 C · 左右虚拟按钮（可选，默认关闭）

**形态**：屏幕左右下角两个半透明圆钮（`ø ≈ 96px`，`opacity ≈ 0.22`），按下即换道。

**收益**：可发现性最高、绝对无歧义、适合无障碍与手部受限玩家。

**代价**：占据画面、与音游沉浸感冲突、边缘误触。

**建议**：作为**设置项**（`设置 → 操控方式 → 虚拟按钮 开/关`），并在**首次游玩引导**中提供一次"要不要开启"的二选一。

## 1.5 通道 D · 键盘（桌面 / 外接键盘）

| 动作 | 按键 |
|---|---|
| 左移一格 | `←` / `A` |
| 右移一格 | `→` / `D` |
| （沿用）跳跃 | `Space` / `↑` |
| （沿用）交互 | `F` |
| （沿用）切场景调试 | `1/2/3/4` |

**实现要点**：**只在检测到键盘事件后才激活桌面通道**，避免与触屏设备的虚拟键盘/输入法冲突。

## 1.6 优先级与仲裁

**总原则**：**低延迟通道永远赢；同一次触摸只产出一个事件。**

```
输入事件
   │
   ├─ 设备判定：最近 3s 内有 keydown → 键盘模式；否则触屏模式
   │
   ▼
[ 通道仲裁 ]
   ├─ 键盘模式：Keyboard 优先（独占，忽略触摸）
   └─ 触屏模式：
        ① TapZone（半区轻点）      ← 最高：1 帧内、零识别
        ② Swipe（横向滑动）         ← 需识别，作为快速连打补充
        ③ 虚拟按钮（若开启）        ← 仅当 ① ② 均未命中（按钮区域外）
   │
   ▼
switchIntent { dir: -1 | +1 }     ← 去重：同一次触摸仅 1 次
   │
   ▼
[ 输入缓冲 ] 动画中按下 → 缓存 1 次
   │
   ▼
LaneController.commit()
```

**仲裁细则**：
- **同优先级冲突**（如同时存在触摸与按钮）→ 按**事件到达时间**先到者胜。
- **多点触控**：只认**第一触点**（`e.changedTouches[0]`），其余触点忽略 → 防止双拇指乱触导致双向连击。
- **触屏 + 虚拟按钮重叠区**：按钮区域优先（因为按钮是显式 UI），非按钮区走 TapZone。

# 2. 跑道数量、布局与切换规则

## 2.1 跑道数量：按难度分档

| 难度 | 跑道数 | 布局（lane index） | 说明 |
|---|---|---|---|
| **Easy** | **3 道** | `-1 / 0 / +1` | 教学档；单次输入跨度小，适合建立节奏感 |
| **Normal** | **5 道** | `-2 / -1 / 0 / +1 / +2` | **默认档**；操作空间足够编排"Z 字连打" |
| **Hard** | **5 道** | 同上 + **特殊道机制** | 音符密度提升；中心道权重更高 |

**为什么不做 7 道**：单次横移距离过大（`7 道 × 2.2m`），在 BPM 118 的八分音符（254ms/拍）下**来不及完成**，会突破"每次输入 = 一次击打"的可判定性前提。

## 2.2 布局参数

| 参数 | 值 | 说明 |
|---|---|---|
| `LANE_W`（道宽） | **2.2 m** | 角色半径约 0.5m，留 1.2m 视觉余量 |
| 角色所在道 x | `(lane - (N-1)/2) × LANE_W` | 3 道 → `-2.2 / 0 / +2.2`；5 道 → `-4.4 / -2.2 / 0 / +2.2 / +4.4` |
| `LANE_Z`（音符生成 z 距离） | 角色前方 **28–36 m**（随难度递减） | 留出反应时间；Hard 更近=更紧张 |
| 中心道（lane 0） | 音符密度 **×1.35** | 音乐重音多落此处，"守住中线"是最优策略之一 |
| 对称性 | 左右完全对称 | 消除手优劣势（尤其在"左手/右手"设备上） |

## 2.3 切换规则

| 规则 | 设定 | 设计理由 |
|---|---|---|
| **单次跨道数** | **仅 1 道**（禁止跨 2 道） | 保证"1 输入 = 1 击打"的判定语义；防止瞬移穿模与判定歧义 |
| **越界** | 禁止（`lane ∈ [0, N-1]`） | 越界给**软反馈**而非无反应（见 §2.4） |
| **硬冷却** | **无** | 硬冷却会**打断连击**；改用"动画时长"天然限流 |
| **输入缓冲** | **1 次** | 动画中再按 → 排队，动画结束立即执行；上限 1 次防止"一键瞬移两格" |
| **空中切换** | **允许**，但 roll 幅度减半 | 保留"空中变向"的爽感，不打断跳跃轨迹 |
| **Hold 期间** | **禁止换道** | Hold Lane 要求"保持"，换道应判 Miss |
| **非法/无效输入** | 不断连击、不扣分 | 玩家不该因为"手滑"被惩罚；仅播放擦边反馈 |

## 2.4 越界"软墙"反馈（关键细节）

在边缘道继续按向外方向时：

1. 角色向目标方向做 **0.35 格**（≈0.77m）的**衰减位移**（不满 1 格）；
2. 附加 **0.06s 的挤压形变**（沿运动轴 `scaleX 1.08 / scaleZ 0.94`）；
3. 播放轻微"擦边"音（低频短促，非惩罚性）；
4. **不断连击、不扣分**。

> 目的：让玩家"感觉到边界"，而不是"以为没反应"。在音游里，"没反应"比"失败"更伤体验。

## 2.5 布局示意

```
      ←  5 道布局（Normal）  →

        -2道    -1道    [0道]    +1道    +2道
      ┌──────┬──────┬──────┬──────┬──────┐
 音符 ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  ← 音符按拍点铺在目标道
      │      │      │      │      │
      │      │      ●      │      │      ← 角色当前在 0 道
      │      │     ↙   ↘  │      │      ← 只能相邻换道（各 1 格）
      │      │      │      │      │
      └──────┴──────┴──────┴──────┴──────┘
           ↕ 2.2m 道宽（固定）
```

# 3. 流畅性与响应

## 3.1 性能指标（硬指标）

| 指标 | 目标 | 说明 |
|---|---|---|
| **输入→画面响应** | **≤ 1 帧（16.7ms @60fps）** | 触摸事件在下一渲染帧即产生位移 |
| **输入识别延迟** | **≤ 33ms（2 帧）** | 含手势判定；TapZone 必须 1 帧内 |
| **单次切换动画** | **110ms** | 太慢显钝，>140ms 会开始积压输入 |
| **输入缓冲** | 1 次 | 保证连续操作不丢输入 |
| **最大有效切换频率** | 约 **9 次/秒**（受 110ms 动画约束） | BPM 118 的十六分音符为 254ms，远低于此上限 → **永不因动画而错过节奏** |

> **关键校验**：`SWITCH_DUR = 110ms` < 最快音符间隔（BPM 126 的十六分 = 119ms）。**即使在最快音符下，动画也能在下一个音符前完成** → 操作层永远不会成为节奏瓶颈。这是本方案能成立的关键数值。

## 3.2 缓动效果

**曲线选择：`easeOutCubic`**（起手快、收尾稳）

```
进度 p ──┐
         │      ╭──────╮
         │    ╭─╯      ╰──╮
         │  ╭─╯            ╰──╮
      0 ─┼──╯                 ╰── 1
      t=0                        t=110ms
   ├─ 手指按下 → 几乎立即启动（0-20ms 内位移可见）
   └─ 尾段缓停，不"弹回"（避免 overshoot 造成眩晕）
```

**参数**：
- `easeOutCubic(t) = 1 − (1 − t)³`
- **禁用**：`easeInOut`（起手延迟致命）、**弹跳/回弹 `elastic/back`**（跑酷中会晕）

## 3.3 角色姿态反馈

| 元素 | 变化 | 目的 |
|---|---|---|
| **Roll（侧倾）** | 换道方向 `±14°`（空中 `±7°`），随进度 `1−p` 衰减至 0 | 方向感与力度感 |
| **Body lean（转身）** | 朝向在 60ms 内转到目标方向（取最短角） | 避免"侧着身子跑" |
| **Bob（跑动起伏）** | 保持原有跑动 bob，不因换道中断 | 维持"一直在跑"的连续感 |
| **纵向速度** | 换道期间**不衰减** | 保证节奏的恒定推进感 |

## 3.4 相机策略（防晕关键）

| 项 | 设定 | 理由 |
|---|---|---|
| **水平（x）跟随** | **不跟随**（相机 x 固定） | 换道频率高，跟随 x 会造成"画面左右甩"→ 眩晕 |
| **垂直（y）跟随** | 不跟随 | — |
| **前进（z）跟随** | **跟随**（见 §3.5） | 维持"世界向后流过"的沉浸感 |
| **相机 Roll** | **≤ ±0.6°**，随换道衰减 | 提供方向感但不至于晕 |
| **FOV** | 换道时**不变** | FOV 变化是晕动症主因 |
| **横向有效速度** | 角色相对相机的横向速度应 **≤ 8 m/s** | 超过会显著增加不适感（参考竞速游戏经验值） |

## 3.5 与"视觉复刻红线"的冲突与解法（⚠️ 必读）

**问题**：本项目北极星是 **1:1 视觉复刻**（定帧构图 `heroC` 逐位不变，红线 R1）。而"自动持续奔跑"天然与**固定定帧机位**冲突。

**解法：平移式跟随机位（保持构图比例恒定）**

- 相机**只沿 z 轴跟随**角色（`camZ = heroZ + fixedOffset`），`y / x / pitch / fov` **全部锁死为定帧基准值**；
- 即：**机位姿态不变，世界向后流动**；
- 这样既获得跑酷的沉浸感，又**保持构图关系恒定**（地平线高度、角色屏幕占比、透视比例不变）。

**门禁影响评估**：
| 项 | 影响 | 处置 |
|---|---|---|
| `?freeze=1` 截图门禁 | `FREEZE` 时 `dt=0`、玩法更新整段跳过 → 角色停在出生点 → **`heroC` 仍逐位不变** | ✅ 红线可保 |
| 门禁的语义变化 | 门禁从"校验游玩姿态"变为"校验**起始定帧**" | ⚠️ 需在开发文档中**显式标注**（不可再声称校验游玩中取景） |
| `palette.py` 视觉回归 | 仍以冻结帧对比 → 有效 | ✅ 保留 |

> **建议**：把自动奔跑与相机平移跟随作为**独立开关**（`AUTO_RUN`），便于 A/B 对比与回退。

## 3.6 掉帧与异常处理

| 情况 | 处理 |
|---|---|
| 掉帧（dt > 33ms） | 切换插值使用**绝对时间**（`(now − t0)/SWITCH_DUR`），**不逐帧累加** → 动画总时长恒定 110ms，不因掉帧变形 |
| 长卡顿（> 300ms） | **不补偿**换道进度（保持当前位置继续），避免"瞬移"；音频同步重锚（见 §4.7） |
| 切后台再回前台 | 暂停游戏 & 音频，重置 `BeatClock.phase`，`last = now`（避免回前台瞬间巨 `dt`） |

# 4. 音乐 × 跑道 × 难度 的玩法设计

## 4.1 核心循环重构

```
角色自动向前
      ↓
前方跑道上按节拍铺开「音符 / 障碍 / 长条」
      ↓
玩家在拍点之间换道「命中音符」
      ↓
Perfect / Good / Miss  →  连击 / 计分 / 评级
      ↓
段落能量上升 → 密度提升 → 副歌爆发 → 结算
```

> **设计核心**：把换道从"位移手段"升级为"**演奏手段**"。玩家不是在"跑"，而是在"用跑道弹琴"。

## 4.2 音符类型（四类）

| 类型 | 视觉 | 玩家动作 | 判定 | 分值 |
|---|---|---|---|---|
| **换道音符**（主） | 目标道上的一块发光音块，带方向箭头 | 在拍点窗口内换到该道 | Perfect/Good/Miss | 300 / 150 / 0 |
| **长条 Hold** | 横跨 2–4 拍的**光带**，标注要待的道 | 进入时判 1 次，**期间不得离开** | 保持成功 | 600（=2×） |
| **障碍 Block** | 挡在某道的能量墙 | **不可进入该道** | 撞到 = Miss | 断连击 |
| **收集 Shard** | 跑道上的音浪晶体 | 进入该道即得 | — | 加分/任务进度 |

**判定时机**：音符**不是"撞上去"，而是"在它的拍点上到达它的道"** → 判定是**时间**的（`now` vs `note.beat`）。

## 4.3 难度 × 节奏编排语法

| 难度 | 跑道 | 音符节奏 | 谱面特征 |
|---|---|---|---|
| **Easy** | 3 道 | **每 2 拍 / 每 4 拍** | 只用二分、四分音符；落点集中在中心与相邻道；**无长条、无障碍** |
| **Normal** | 5 道 | **每 1–2 拍** | 出现八分音符对（连续两次快速左右）、少量 Hold、稀疏 Block |
| **Hard** | 5 道 | **每 0.5 拍（八分）～1 拍** | 十六分连打段、**Z 字蛇形**、Hold + Block 组合；副歌几乎无空隙 |

## 4.4 三首内置曲的段落编排（结合现有曲目）

### 《晴天》BPM 118（舒缓）· desert — 教学与铺垫

| 段落 | 难度 | 编排 | 操作要求 |
|---|---|---|---|
| Intro (0–20s) | Easy | 每 4 拍 1 音符，只在 `-1 / 0 / +1` | 建立"拍点=换道"直觉 |
| Verse (20–60s) | Normal | 每 2 拍，出现"0 → ±1" | 稳定四分/二分 |
| Pre-Chorus (60–72s) | Normal | 加密，出现**第一个 Hold**（2 拍） | 教"保持不动" |
| **Chorus (72s–)** | Normal→Hard | **八分音符为主**；中心道连打 + **左右 Z 字** | 连续左右交替，视觉"随旋律摇摆" |

**创意编排 · Chorus**：中心道密集音符要求"原地不换道"，紧接一段"左右横跳 Z 字"——**密集静止 → 剧烈摆动**的对比，制造副歌的"爽点"。

### 《夜曲》BPM 126（中速摇摆）· cave — 障碍与 Hold

- **特色**：**Swing 感**（八分三连音 feel）→ 谱面用**"短-长-短"附点节奏**做律动
- **障碍设计**：对应洞穴岩壁 → 每 2 拍一个 Block，**强制换道**，逼出连续反应
- **创意**：**Hold Lane 跨洞穴** —— 一条发光路径横跨通道，必须**保持在同一条道 2 拍**才能通过
- **难度**：副歌段用 `Z 字 + 障碍夹击`（左右都是墙，只能往中间穿）

### 《稻香》BPM 110（慢速）· base — 收束与优雅

- **慢 BPM = 大幅移动** → 编排**大跨度 Hold**（跨 2–3 道的长时间保持）
- 障碍为柔和的"稻穗墙"（视觉弱化，不打断氛围）
- 整体 **Easy–Normal**，高潮短促，结尾一个 **4 拍长 Hold"鞠躬"** 作为收束

## 4.5 音乐与操作的四条联动机制

### ① 重音驱动"必须换道"（On-beat Lane Change）
- 段落主重音（kick / 军鼓）落点生成**强制音符**：目标道 ≠ 当前道
- 该拍若有 Block，则玩家**必须**在精确窗口内换到安全道
- → **大鼓重音 = 玩家心跳点**，操作与音乐骨架同频

### ② 音符连打（Stream）
- 连续八分音符 → 连续快速换道，设计成**"镜像往返"**（在两相邻道间来回）
- 最易上手、视觉最流畅；Hard 可扩展为 3 道蛇形

### ③ Hold Lane（张弛交替）
- 横跨数拍的光带，要求"到达后**不再操作**"
- 与连打形成**被动/主动交替**，避免全程手指忙碌
- 节奏设计上：连打段 → Hold → 连打段，形成**呼吸感**

### ④ 段落能量同步视听与操作强度
- **RMS 能量高（副歌）** → 跑道视野开阔 + 音符密度↑ + 背景色更亮 + 障碍密度↑
- **能量低（主歌）** → 跑道收窄 + 音符稀疏 + 障碍少
- → **难度跟着音乐能量走，而不是平均分配**

## 4.6 谱面生成算法（可执行规格）

```
输入：Analysis { onsets[], energies[], bpm, sections[] }
参数：difficulty, lanes, LANE_W, SWITCH_DUR

for each onset t_i:
    beat_i = t_i / (60 / bpm)
    strong = (onset 是 kick/snare)        # 由频谱低频能量判定
    E = section_energy(sections, t_i)     # intro .3 / verse .6 / chorus 1.0 / outro .4
    density = base_density(difficulty) * E

    # ① 强制换道
    if strong and rand < 0.75:
        emit 换道音符(target ≠ curLane)
    elif not strong and rand < 0.25:
        emit 装饰音符(不计分)

    # ② Hold（每 8 拍小节起点 或 副歌起点）
    if beat_i % 8 == 0 or isChorusStart:
        emit Hold(dur = 2~4 拍, lane = 邻近可用道)

    # ③ Block（强 onset 概率更高；永不堵死所有道）
    if beat_i % (4~8) == 0 and strong_prob and freeLanes ≥ 2:
        emit Block(随机 1 道)

    # ④ 可达性校验（关键！）
    Δlane = |targetLane − curLane|
    if (nextNoteBeat − beat_i) < (Δlane × SWITCH_DUR × 1.2):
        targetLane = 更靠近 curLane 的道        # 或延后到下一个可用拍
```

**可达性校验是音游跑酷的灵魂** —— 不做校验就会生成"物理上赶不及"的谱面，直接摧毁体验。

## 4.7 音乐与判定的时间基准（实现细节）

**关键点**：玩家**无法控制到达时刻**，只能控制"何时发起换道"。所以判定要补偿半个切换时长。

```
玩家在 t 时刻按下换道
  → 角色约在 t + SWITCH_DUR/2 抵达目标道中心
  → 判定 = |(t + SWITCH_DUR/2) − noteTargetTime|
```

| 判定 | 时间偏差 | 换道语义 |
|---|---|---|
| **Perfect** | ≤ 80ms（或 ≤ 0.15 拍） | 精确踩点 |
| **Good** | ≤ 160ms | 略偏 |
| **Miss** | > 160ms / 撞 Block / Hold 期间离开 | 断连击 |

**长音频漂移处理**：超过 30s 的关卡需在每小节用 `AudioContext.currentTime` **重锚** `BeatClock.phase`，避免 `setTimeout/RAF` 累积误差（长期漂移会导致判定系统性偏移）。
