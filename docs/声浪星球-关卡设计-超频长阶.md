## §0 定位说明（先读）

| 问题 | 回答 |
|---|---|
| 这是什么 | **一个具体关卡**的完整设计：《超频长阶》（Overdrive Causeway） |
| 它解决什么 | 玩家"在跑酷但没在听歌"——现有玩法把注意力分散到横向决策上 |
| 核心手段 | ① 取消分赛道 → 决策维度还给**时间**；② 镜头由音乐驱动 → 让"结构"变得可感；③ 误导体 → 用设计区分"听"与"看" |
| 与既有关系 | **新增玩法模式**。既有 desert / cave 的换道模式**保留**，是否全面替换见 §9.4 |
| 红线 | 本关卡是**新场景**，不触碰既有 4 场景几何 → 门禁 1（`heroC` 零漂移）不受影响 |

## §1 设计目标与四条要求

### 1.1 原始需求 → 设计应答

| # | 需求 | 设计应答 | 对应章节 |
|---|---|---|---|
| 1 | 取消分赛道，改单一超长赛道 | 赛道宽 3.5 m、无道分割线、无限延伸；**唯一决策维度 = 时间** | §3 |
| 2 | 整体节奏偏快、速度感强 | BPM 158 · 基础前进 **11 u/s** · 冲刺 15 u/s · FOV 70→92 动态拉伸 | §3.3 |
| 3 | 布置大量障碍物 | 6 类障碍 · 密度 = `基础难度 × 段落能量` · 高潮段 **≥ 1 个/拍** | §4 |
| 4 | 按节奏/旋律/情绪触发不同视角 | 5 种镜头 · 由 `Analysis` 三通道驱动 · **只在乐句边界切换** | §5 |
| 5 | 强调玩家对音乐的理解 | 三层机制：预判窗口 / 同调长按 / 误导体 | §6 |

### 1.2 一句话设计意图

> 分赛道问的是"**往哪躲**"，超频长阶问的是"**下一拍会发生什么**"。
> 前者考反应，后者考理解。

## §2 与既有"分赛道"方案的关系

### 2.1 为什么取消分赛道

| 分赛道（M3-OP）的问题 | 单赛道（本设计）的收益 |
|---|---|
| 横向是"空间决策"，与音乐的**时间结构**无关 | 空间被固定 → 玩家注意力 100% 投向**时间轴** |
| 5 条道产生"安全区"，玩家可长期待在同一道躲避 | 无安全区 → 每一次规避都必须**回答音乐的提问** |
| 换道是"1 输入 = 1 击打"，但语义是空间位移 | 升降是"1 输入 = 1 状态翻转"，语义直接是**节奏应答** |
| 视角固定（刚 z 跟随），与音乐无关 | 视角成为**音乐信息的编码器**（§5） |

### 2.2 范式对照

| 维度 | M3-OP 分赛道 | 本关卡单赛道 |
|---|---|---|
| 空间自由度 | 5 条离散道（横向） | **0**（横向锁定，仅 ±0.35 m 视觉微移） |
| 操作维度 | 左 / 右 | **升 / 降 / 同调长按** |
| 单输入语义 | 横向位移 | **纵向状态翻转** |
| 决策依据 | 障碍所在道 | **音乐事件时刻** |
| 镜头 | 单一刚性跟随 | **5 种镜头状态机** |
| 信息可得出处 | 视觉为主 | **听觉为主、视觉为辅**（视角会主动限制视野） |

### 2.3 术语

- **Lo 层 / Hi 层**：赛道的两个高度层（贴地层 / 悬浮层），角色在其中之一。
- **闸门（Gate）**：横跨赛道的障碍；低位闸门需升到 Hi，高位闸门需降到 Lo。
- **误导体（Decoy）**：视觉像障碍、但与音乐事件不对齐的**无害**物体。
- **乐句（Phrase）**：4 小节为一个乐句，是镜头切换的**最小边界单位**。

## §3 赛道与操作范式

### 3.1 赛道形态

```
        ┌─────────────────────────────────────┐
  远  ←  │  无限延伸 · 分段拼接（每段 24 m）      │
        │  ─────────────────────────  Hi 层    │  ← 悬浮层（轨道面 +0.9 m）
        │  ═════════════════════════  Lo 层    │  ← 贴地层（轨道面）
        └─────────────────────────────────────┘
        宽 3.5 m · 无道分割线 · 中央仅一条引导光带
```

- **宽度**：3.5 m（略窄于既有可玩带，强化"专注"与"速度感"）
- **层级**：`lo`（贴地）与 `hi`（+0.9 m 悬浮），角色同一时刻只在一个层
- **表面**：中央一条发光引导带随 BPM 脉冲流动（速度感的视觉来源之一）
- **分段**：每 24 m 为一段，程序化拼接；段间无接缝（`dseq` 独立随机流，见 R2）

### 3.2 操作映射

| 操作 | 语义 | 移动端 | 键盘 | 判定意义 |
|---|---|---|---|---|
| **升 Lift** | 切换到 Hi 层 | 上滑 / 上半屏轻点 | `↑` / `W` | 规避低位闸门 |
| **降 Dive** | 切换到 Lo 层 | 下滑 / 下半屏轻点 | `↓` / `S` | 规避高位闸门 |
| **同调 Resonate** | 长按贴合旋律 | 长按屏幕任意处 | 长按 `空格` | 旋律长音处取值 |
| *（隐藏）不操作* | 保持当前层 | — | — | **双闸门夹击时，"不操作"才是正解** |

> **设计要点**：引入"**不操作也是有效输入**"（双闸门 Twin），打破"见障碍就按"的条件反射，迫使玩家**判断**而非**反应**。

### 3.3 手感与速度数值

| 参数 | 值 | 说明 |
|---|---|---|
| 基础前进速度 | **11 u/s** | 约为 M3-OP（4.5）的 2.4 倍 |
| 冲刺（高潮段自动） | 15 u/s | 由段落能量驱动，非玩家操作 |
| 层间切换时长 | **90 ms** | 快于换道（110 ms），因整体节奏偏快 |
| 切换缓动 | `easeOutCubic` | 禁用 elastic/back |
| 角色俯仰 | ±12°（随切换进度衰减） | 升起抬头 / 下降俯冲 |
| FOV | 70 → **92**（随速度/能量插值） | 速度感的主要来源 |
| 输入缓冲 | 1 次 | 动画中按键排队一次 |
| 越界（已在 Hi 再按升） | 软反馈：+6° 额外仰角 + 提示音，**不断连击** | 沿用"软墙"哲学 |
| 最短障碍间隔 | **1 拍** = 380 ms @158 BPM | 校验：380 ms ≫ 90 ms 切换 → 操作层不成为瓶颈 |

> **关键校验**：`switchMs(90) < 最短音符间隔(95 ms, 十六分 @158BPM)` → 即使在最密段，玩家也能从容完成切换。

## §4 障碍系统

### 4.1 六类障碍

| 类型 | 形态 | 正解 | 判定对象 | 首现段落 |
|---|---|---|---|---|
| **低位闸门 `gate-lo`** | 贴地横梁（高 0.7 m） | **升** 到 Hi | 升的时机 | 前奏（教学） |
| **高位闸门 `gate-hi`** | 悬空横梁（离地 0.9 m） | **降** 到 Lo | 降的时机 | 前奏（教学） |
| **双闸门 `twin`** | 上下夹击、中间留缝 | **不操作**（保持层） | 是否误操作 | 高潮 |
| **连环柱 `pillar`** | 3–5 连交替闸门 | 节奏化起落 | 连续判定（可累计连击） | 预副歌 |
| **脉冲球 `orb`** | 可收集，落在音符上 | 穿过即得 | 收集判定 | 主歌 |
| **误导体 `decoy`** | 像障碍 **但无害**（与音乐不对齐） | **忽略** | 撞上不扣分 | 副歌 |

### 4.2 误导体（Decoy）—— 本关卡的灵魂装置

```
音乐事件轴:   ●───────●───────●───────●      （onset 真实落点）
视觉障碍轴:   ◆──◆────◆───◆──────◆──◆       （含错位假障碍）
                   ↑ 与 onset 不对齐 = 必须无视
```

- **布置规则**：`decoy` 被放在**非 onset** 位置，其"看起来该躲的时刻"与音乐无关；
- **代价设计**：撞上 `decoy` 只产生视觉火花，**不扣分、不断连击**；
- **真正的惩罚是间接的**：若玩家为了躲 `decoy` 而错过了紧邻的真实闸门，就会 **Miss**；
- **设计意图**：让"凭视觉反应"的玩家吃亏，让"跟着音乐呼吸"的玩家受益——**用机制而非说教筛选玩家行为**。

### 4.3 密度公式

```
density(section) = difficultyBase × section.energy
障碍间距(拍)      = clamp(round(1 / density), 1, 8)
障碍落点          = Analysis.onsets 中与目标拍点最近的 onset
```

| 段落能量 | 障碍间距 | 主观感受 |
|---|---|---|
| 0.2–0.4 | 4–8 拍 | 稀疏、铺垫 |
| 0.5–0.7 | 2–3 拍 | 稳定咬合 |
| 0.85–1.0 | **1 拍** | 极限、速度感峰值 |

- 所有障碍视觉标记走 **`dseq(seed = songId + ':' + sectionIndex)`** 独立随机流，不消耗全局 `rnd()`（遵守 R2）。
- 障碍落点**必须对齐 onset**，若最近 onset 偏差 > 半拍则该拍不放障碍（宁缺毋滥）。

## §5 视角系统（核心 A）

### 5.1 五种镜头

| 镜头 | 相机位置 | 主要触发来源 | 视野特征 | 玩法代价 |
|---|---|---|---|---|
| **追尾 Chase** | 角色后 3 m、上方 1.6 m | 默认 / 低能量段 | 标准 | 无 |
| **贴身 Onboard** | 角色后 0.4 m（近第一人称） | **情绪**：能量 ≥0.85 且频谱质心高 | FOV 拉满、速度感最强 | **前方可见距离缩短 40%** |
| **俯视 Overhead** | 角色上方 6 m、45° 俯角 | **旋律**：音高斜率 < −0.3 且持续 ≥2 小节 | 看到前方全局布局 | 角色比例变小，精细操作变难 |
| **侧视 Lateral** | 角色侧向 4.5 m 平移 | **旋律**：音高斜率 > +0.3 / 桥段 | 障碍呈剪影、纵深感弱 | **看不到上下层差异** |
| **漂移 Drift** | 角色斜后 6 m、缓慢环绕 | **结构**：段落交界前后各 1 小节 | 呼吸感、视野开阔 | 弱（用于蓄势） |

### 5.2 触发与仲裁

```
每帧读取 Analysis 三通道
  ├── 节奏：onset / kick 强度   → 不切镜头，仅"强拍脉冲"（zoom ±3%）
  ├── 旋律：音高斜率 slope      → 候选 [俯视 | 侧视 | 漂移]
  └── 情绪：能量 energy + 质心  → 候选 [贴身 | 追尾]
        │
        ▼
   仲裁器 LensArbiter
   ┌──────────────────────────────────────┐
   │ ① 仅在乐句边界（4 小节线）允许切换         │
   │ ② 冷却 ≥ 2 小节                        │
   │ ③ 能量优先级 > 旋律优先级 > 默认追尾       │
   │ ④ 段内保持稳定，禁止抖动                  │
   └──────────────────────────────────────┘
```

**硬约束**：
- **只在乐句边界切换** —— 镜头跟着**音乐结构**走，而非任意时刻跳变。这本身就是"结构可视化"。
- 切换时长 **180 ms**，缓动 `easeInOutSine`（比操作慢，因为它是"运镜"而非"操作"）。
- 同一乐句内最多切换 **1 次**。

### 5.3 设计意图：视角即信息闸门

> **镜头不是为了好看，而是为了改变"你能看到什么"。**

- **贴身** 收窄视野 → 逼玩家**靠听**；
- **侧视** 抹平上下层 → 逼玩家**靠记忆**；
- **俯视** 给全局 → 奖励**会规划**的玩家；
- **漂移** 给空白 → 让玩家**喘一口气**并为下一段蓄势。

视角的周期性切换，构成一条"**看得多 ↔ 听得清**"的张力曲线——这正是"考验对音乐结构的把握"的机制载体。

### 5.4 防眩晕

- 切换频率上限：≤1 次 / 乐句（4 小节 ≈ 6 s @158 BPM）
- 禁止 `roll` 与 `yaw` 同时大幅变化
- 提供辅助选项：**固定追尾**（关闭自动切换，供易晕用户）

## §6 音乐理解机制（核心 B）

三层机制，从"预判"到"贴合"到"辨识"：

### 6.1 预判窗口（Anticipation）

| 项 | 规则 |
|---|---|
| 出现时机 | 段落交界前 **2 拍** |
| HUD 提示 | 走向符号：`↑` 上行 / `↓` 下行 / `~` 持续（来自旋律斜率预测） |
| 玩家操作 | 在窗口内**长按"同调"**完成押注 |
| 押对 | 下一段得分倍率 **×1.5** |
| 押错 | **无惩罚**，倍率 ×1.0 |
| 不押 | ×1.0 |

> **设计要点**：**只奖励理解，不惩罚失手**。降低挫败，同时让"听懂结构"的玩家获得显著优势。

### 6.2 同调长按（Resonate）

| 项 | 规则 |
|---|---|
| 触发条件 | 旋律**持续音**（音高方差低 ≥1 拍） |
| 操作 | 按住"同调"键，贴合旋律线 |
| 松手时机 | 须落在**长音结束的拍点** |
| Perfect | 松手偏差 ≤ 80 ms |
| Good | ≤ 160 ms |
| Miss | > 160 ms / 未按 |

> **设计要点**：考验玩家对"**旋律呼吸长度**"的体感——这是纯反应游戏无法考察的能力。

### 6.3 误导体辨识（Decoy）

见 §4.2。**不按音乐、只按视觉反应的玩家会在这一层持续失分。**

### 6.4 三层与能力对应

| 机制 | 考察能力 | 音乐术语 |
|---|---|---|
| 预判窗口 | 结构预判 | 曲式（form） |
| 同调长按 | 乐句体感 | 乐句 / 呼吸（phrasing） |
| 误导体 | 听觉优先级 | 节奏对齐（groove） |

| 标准 | 1.0× | 1 拍 | 开启 | 开启 |

### 7.4 计分

沿用开发文档 §5.4 判定窗口，新增两个乘区：

```
最终得分 = Σ(判定分 × 同调倍率 × 预判倍率)
同调倍率 = 1.0 + 0.5 × (同调Perfect数 / 同调总数)
预判倍率 = ×1.5（押对）/ ×1.0（其余）
```

评级沿用 S / A / B / C（`acc` 口径不变）。

## §8 数据结构扩展

### 8.1 关卡与段落

```js
Level = {
  id: 'causeway',
  mode: 'single-track',                 // ← 与 'lanes' 并列的模式枚举
  songId, bpm, offset,
  track: { width: 3.5, speed: 11, sprintAt: 0.85, layers: ['lo','hi'] },
  switchMs: 90,
  sections: [ Section, ... ]
}

Section = {
  t, dur, kind,                         // 起点(秒)/时长/类型
  energy,                               // 0..1，来自 Analysis
  density,                              // 障碍密度
  camera: 'chase'|'onboard'|'overhead'|'lateral'|'drift',
  cameraCue: { from:'melody'|'mood'|'form', slope:-0.42 },  // 触发来源（可解释、可调试）
  obstacles: [ Obstacle, ... ],
  anticipation: { at, dir } | null      // 预判窗口
}

Obstacle = {
  id, beat, z,
  layer: 'lo'|'hi',                     // 所在层（占用哪一层）
```

### 9.2 关键实现约束

1. **玩法逻辑仍须包在 `if (!FREEZE){...}` 内** → 定帧零漂移不受影响。
2. **新增场景 `causeway` 需要独立基线**：首次完成后跑 `quad.js` 记录该场景 `heroC` 为新基线，此后受 R1 保护。
3. **镜头切换不得在 `?freeze=1` 下执行**（`dt=0` 自然满足）。
4. 新增视觉元素（闸门/轨道光带）走 `dseq(seed)` 独立随机流（R2）。

## §11 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 镜头频繁切换导致 3D 眩晕 | 用户流失 | 切换 ≤1 次/乐句；提供"固定追尾"辅助；禁止 roll+yaw 同时大幅变化 |
| 速度过快（11 u/s）导致反应不及 | 挫败 | 前奏 18 s 教学段；三档难度；最短间隔 1 拍（380 ms）已校验 |
| 误导体被误解为 bug | 困惑 | 首次遇到时给一次性说明字幕；撞上时给明确视觉反馈（火花 + "无害"图标） |
| 单赛道玩法单一 | 重复可玩性低 | 靠**音乐本身**提供变化（换歌即换关）；段落机制轮转（教学/预判/连环/误导体/同调/双闸门） |
| 与既有换道模式割裂 | 品牌一致性 | 方案 A 并存；共享 HUD 与判定数值；仅操作维度不同 |
| 视角切换与障碍不可见冲突 | 不公平感 | 侧视/贴身段**降低障碍密度**（保证"看不见也能听出来"）；切换前给 0.5 s 预兆 |
| 音频分析新增三通道算力 | 移动端卡顿 | 离线 `OfflineAudioContext` 预计算；`melody/mood` 下采样到 20 Hz |
